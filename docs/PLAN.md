## 5. Как работаем

| Шаг | Кто | Правило |
| --- | --- | --- |
| Задача | по этому плану сверху вниз; поломка — вне очереди | одна задача — одна ветка и один PR (правило 6) |
| Решение | Claude пишет ADR или дополнение, владелец отвечает | архитектура — до кода (правило 1); мелкая правка — сразу |
| Код и тесты | Claude | `python -m unittest discover -s tests` зелёный локально до пуша; разбор табло — ещё и на настоящей записи |
| Независимая проверка | агент-ревьюер (`/code-review`) для PR, которые трогают службы (`bot.py`, `clips.py`, `server.py`, `live.py`) или данные о людях | Claude сливает сам (правило 8), поэтому второй взгляд — до слияния |
| Слияние и выкладка | Claude сливает, `deploy.yml` выкладывает | в ответе — что изменится у болельщиков и что проверить |
| Проверка после выкладки | Claude — по `/api/live/*`, пульту агента и запускам Actions; владелец — в боте | что не сошлось — новый PR, а не правка руками на сервере |

Сессии Claude — в окружении **Default**: в нём `RHL_AGENT_TOKEN`, `RHL_API` и доступ к домену API. Сервер руками
меняет только владелец: всё остальное идёт через PR и выкладку.
