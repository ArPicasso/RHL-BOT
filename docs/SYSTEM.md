# Как устроена система сейчас

Состояние на 03.10.2026, первый день сезона 2026/27. Здесь то, что реально работает, и как
этим управлять. Почему так решили — в `docs/adr/`, куда растём — в `docs/ARCHITECTURE.md`.

## Схема

```
                     GitHub (ArPicasso/RHL-BOT)
   слияние в main ──┬──▶ «Тесты»
                    ├──▶ «Мини-апп» (pages.yml, ещё раз в час) ──▶ GitHub Pages
                    │      сайт лиги, r-hockey, t.me/s  ──▶  webapp/data/*.json
                    └──▶ «Выложить бота на сервер» (deploy.yml) ──ssh──┐
                                                                       ▼
 болельщик ── Telegram ── мини-апп (Pages)            VPS в России (Timeweb, Новосибирск)
     ▲                         │                       /opt/rhl, служба bot (bot.py)
     │                         │                         │  читает data/*.json с Pages
     └──── Telegram Bot API ◀── зарубежный сервер ◀──────┘  через tg-tunnel (SOCKS 127.0.0.1:1080)
                               │
                               └─ https://<хост>/api ──▶ Caddy :443 ──▶ служба api (server.py, 127.0.0.1:8080)
                                  зачёт, прогнозы, живое        state.db · live/*.json ◀── служба live (live.py)
```

## Части

### Мини-апп — GitHub Pages

- Код — `webapp/`, без сборки. Адрес — `https://arpicasso.github.io/RHL-BOT/`.
- Вкладки: «Главная» (лист дня и лента лиги), «Календарь», «Таблица», «Раскат», «Я». Экран команды
  открывается из таблицы и календаря.
- Данные собирает задание **«Мини-апп»** (`.github/workflows/pages.yml`) при каждом слиянии в `main`
  и раз в час, а с сервера ещё каждые 15 минут: служба `pages` (`pages_kick.py`) зовёт
  `workflow_dispatch`, потому что cron GitHub теряет запуски (ADR-015, дополнение 03.10). Нужен токен
  `PAGES_TOKEN` в `/etc/rhl/bot.env`. Шаги задания:
  1. `league.py` — протоколы и лидеры со старого движка `nmhl.fhr.ru`, только если задана `LEAGUE_SITE`.
  2. `rhl_site.py` — матчи, протоколы сыгранных и лидеры сезона с `rhl.fhr.ru` (кэш `rhl_site.json`,
     лидеры — в `leaders.json`). Протокол сыгранного матча не разобрался — в журнале «протокол <id> не
     разобран: <чего нет>», а сама страница — в артефакте запуска `rhl-protocol-unparsed` (три дня).
  3. `tg_channels.py` — посты каналов клубов.
  4. `build_data.py` — `league.json`, `h2h.json`, `matches/`, `feed/`. Календарь пока берётся с r-hockey.ru,
     последний удачный — в кэше `rhockey.json`.
  5. `build_raskat.py` — расклады «Раската» в `data/raskat/`.
  6. Метка версии для кэша и публикация.
- Новый запуск сборки снимает прежний (`cancel-in-progress`), у сборки и выкладки — ограничение по времени. 06.10
  утром и с 22:58 06.10 до 14:47 07.10 выкладка висела в ожидании окружения `github-pages` и держала очередь: все
  следующие сборки отменялись, мини-апп не обновлялся 4 и 16 часов. Теперь такой запуск снимает следующий, через
  15 минут.
- Если r-hockey не ответил, сборка идёт по календарю прошлой удачной сборки из кэша `rhockey.json`.
  Падает, только если кэша нет. До 04.10 падало всё задание: 03.10 — раз за 25 запусков, 04.10 — в 12:43.
- Служба `pages` не может разбудить сборку — тревога «Служба pages не может запустить сборку» с причиной.
  Чаще всего это ответ GitHub 401/403/404: у `PAGES_TOKEN` нет доступа к репозиторию `ArPicasso/RHL-BOT`
  или права Actions: Read and write. Лечится новым токеном в `/etc/rhl/bot.env` и `systemctl restart pages`.

### «Раскат» — игра дня (ADR-018)

- Головоломка: одна шайба проходит весь лёд и задевает номера по порядку. Каждый день новый
  расклад, прошлые дни — тренировка.
- Работает **без сервера**. Расклад выводится из даты (соль — секрет `RASKAT_SALT`), путь
  проверяется на телефоне. Решения в опубликованных файлах нет.
- **Зачёт** — служба `api` на VPS (`docs/raskat/contract.md`, раздел 5). Включается переменной
  Pages `RASKAT_API=https://<хост>/api/raskat`: тогда мини-апп показывает зачёт дня, кубок клубов и
  дуэли, а бот один раз зовёт лист ожидания. Пусто — играем без зачёта, как раньше.
- Соль: секрет `RASKAT_SALT` задания Pages и `RASKAT_SALT` в `/etc/rhl/bot.env` — одно значение.
  Сервер при старте и раз в час сверяет свой расклад дня с опубликованным; разошлись — проверяет
  пути по опубликованным файлам дня и пишет об этом в `/api/health`. «Временно выключен» — только
  если опубликованный файл не читается.
- В боте: `/raskat` и кнопка «Собрать раскат», лист ожидания зачёта — `raskat_waitlist.json`.

### API — VPS в России (ADR-019, ADR-020)

- `server.py`, aiohttp, слушает только `127.0.0.1:8080`. Наружу — через Caddy по HTTPS
  (`https://<хост>/api/…`, сертификат Let's Encrypt сам). Ставит Caddy `deploy/https.sh`.
- `/api/raskat/*` — зачёт «Раската», `/api/predict/*` — «Кто победит?», `/api/live/*.json` —
  живые файлы матч-центра из `live/` (их пишет служба `live`, `live.py`), `/api/health` — жив ли,
  `/api/admin/status` — пульт админа, `/api/seen` — счётчик открытий мини-аппа (ADR-021).
- Вход — подпись `initData` Telegram (токен бота), CORS — только адрес Pages (`PAGES_ORIGIN`).
- Хранит всё в SQLite `/opt/rhl/state.db`: результаты раскатов, настройки, коды дуэлей, голоса, «Мой игрок» (`my_player`).
  О человеке — Telegram id, клуб и (только по галочке) «Пётр К.». Стирается кнопками «Удалить мои
  раскаты» (`DELETE /api/raskat/me`) и `DELETE /api/predict/me`.

### Бот — VPS в России

- `@rhl_u21_bot`, `bot.py`, aiogram 3, long polling. Встречает, ведёт в мини-апп, показывает
  матчи дня, напоминает о матчах выбранных команд, после матча присылает счёт, отвечает на
  `/leaders` и `/raskat` (ADR-005, ADR-019, раздел 8).
- **Команды** (в меню их нет, они в тексте и на кнопках): `/today` — матчи лиги сегодня со временем
  МСК, статусом, счётом и ссылками на трансляции, нет матчей — ближайший игровой день; `/team` —
  выбрать до трёх команд для напоминаний; `/remind` — что включено, «Выключить». Диплинки
  `?start=today`, `?start=remind` («Рязань-ВДВ»), `?start=remind-<id команды>`.
- **Подписчики** — `subscribers.json`: `{"<chat_id>": ["ryazan-vdv", …]}`. Старый список `[chat_id]`
  бот при запуске сам переписывает в подписку на «Рязань-ВДВ». «Выключить» или блокировка бота
  убирают chat_id из файла целиком.
- **Напоминания** в 19:00 накануне и в 10:00 в день игры — по `league.json` с Pages (время начала,
  город, «Смотреть», кнопки «Кто победит?» и «Текстовая трансляция»), время уточняет
  `live/<дата>.json` и `live/schedule.json`. Pages не ответили — «Рязань-ВДВ» по `games.json`.
- **Живое** бот читает с диска: `LIVE_DIR` (по умолчанию `/opt/rhl/live`), файлы пишет служба `live`.
  Нет файлов — бот работает без статусов и счёта по ходу. Файл старше 20 минут — без хода матча.
- **Финал**: по протоколу (как раньше) или когда онлайн держит «окончен» с тем же счётом 10 минут
  подряд — тогда с пометкой «по данным онлайна лиги». Протокол потом второго сообщения не шлёт:
  в `announced.json` и id матча, и ключ `<дата>|<хозяева>|<гости>`. Пишет только болельщикам
  команд матча.
- Сервер: Timeweb, Новосибирск, Ubuntu 24.04. Ставится скриптом `deploy/setup.sh` (`BOT_README.md`).
- **Telegram из России закрыт.** Бот ходит в Bot API через службу `tg-tunnel`: это SSH-туннель
  на зарубежный сервер, тот же, где стоит Amnezia VPN. Ставит туннель `deploy/tunnel.sh`.
  Ключ туннеля на зарубежном сервере умеет только проброс портов.
- Календарь, результаты, лидеров и раскат дня бот берёт с Pages (`WEBAPP_URL`) напрямую, без
  туннеля, не чаще раза в 10 минут; `live/` смотрит раз в минуту. С 23:00 до 9:00 МСК молчит.
- Письма болельщиков (ADR-025): бот не понял сообщение — предлагает кнопку «Написать живому
  человеку»; нажал — следующее сообщение уходит `ADMIN_IDS` (текст и ссылка для ответа, без имени и
  `@username`). Одно письмо за нажатие, не чаще раза в десять минут, до 1000 знаков, только текст.
  Нет `ADMIN_IDS` — кнопки нет. Команда `/pismo` — то же самое для тех, кто её знает.
- Голы по ходу матча (ADR-024): из `live/<дата>.json` (события `kind: "goal"`) подписчикам команд
  этого матча, по умолчанию включены, выключаются кнопкой в `/remind` (`goals_off.json`). Гол старше
  десяти минут пропускаем молча, больше трёх голов одного матча за проход не шлём, ночью молчим.
  Событие отмечаем до отправки: перезапуск не пришлёт гол дважды.
- Повторы голов (ADR-027): `/replay` для `ADMIN_IDS` — матч, затем одним сообщением ссылка на запись VK и
  времена всех голов по порядку (или гол и его время). Голы того же периода без времени бот досчитывает
  по времени, когда служба `live` заметила смену счёта, и сразу присылает все ссылки на проверку. Каждая отметка —
  время, «нет в записи», «табло сбилось», ответ на превью — строка журнала `goal_marks` в `state.db` (ADR-033): кто,
  когда, что прислал или какое окно превью видел. Строки не меняются и не удаляются (триггеры); ошиблись — у гола в
  `/replay` история отметок и «Отозвать», отметка остаётся в истории отозванной; перепроверил и время верное —
  «✅ Время верное»: та же секунда записывается от того, кто нажал. Матч старше трёх дней —
  `/replay ДД.ММ`, хоть начала сезона. `/marks_forget <id>` стирает Telegram id ушедшего админа или помощника, у
  отметок остаётся роль. Отметки до журнала перенесены в него один раз как «не проверено». Служба `clips` проверяет
  каждую отметку табло и ходом часов (`checks` в `live/clips.json`): «сошлось», «не проверено», «нечем проверить» или
  «спор» — тогда точной секунды у гола нет ни от отметки, ни от табло, а бот один раз пишет отметившему обе версии
  (`disputes.json`). При вводе бот проверяет порядок голов, ход часов, сдвиг к сайту и дубли и предлагает кнопками
  вероятные опечатки.
  Из журнала бот собирает `live/replays.json` (в бэкапе), API отдаёт его как
  `/api/live/replays.json`, сборка Pages ставит «Повтор» у голов в разборе матча и под «Ходом матча», а до
  протокола — в ленте матча (ADR-028). Запись лиги из `league.json` бот подставляет сам — достаточно прислать
  времена. Раз в день, в первую минуту после 21:00, когда такие есть, админам приходит «Ждут превью: 7 голов в
  3 матчах» (голы, у которых табло нашло смену счёта, но секунды нет ни у табло, ни у админа, — ответ на превью в
  чате), «Табло не размечено: Полёт (2), …» — клубы, чьи домашние матчи ждут разметки табло (ADR-030, дополнение
  06.10), и «Без превью, табло не разобрало: …» — окончен, есть запись лиги, нет ни секунд, ни превью (ADR-030,
  раздел 7). Кнопка на матч открывает его в `/replay`. После 23:00 молчит, перезапуск не повторяет (счётчик
  `replay_nag` в `status/bot.json`). На пульте — те же числа плитками.
- Итог матча с протоколом — две кнопки: «Как это было» и «🎬 Голы матча» (`?match=<id>&view=goals`): мини-апп
  открывает разбор и играет клипы голов подряд; клипов ещё нет — голы с «Повтором» (ADR-030, раздел 6).
- «Мой игрок» (ADR-030, раздел 6): звёздочку на странице игрока мини-апп повторяет на сервер
  (`PUT /api/me/player`, таблица `my_player` в `state.db`, `myplayer.py`). Бот раз в минуту смотрит `league.json`:
  гол отмеченного игрока (автор, без буллитов) в матче с отметки, не старше двух дней — отметившему клипом по адресу
  из хранилища (Telegram качает его сам, дальше — `file_id`), а нет клипа через 8 часов после начала матча —
  текстом с «Повтором» в VK. Кому что ушло — `reminded.json` (`<дата матча>:player`). Связь стирают снятие
  звёздочки, «Выключить» в напоминаниях и блокировка бота. На пульте — только число отметивших.
- Зовы (ADR-023), по одному на человека в день: в «Раскат» — с 11:00 до 21:00 тем, у кого стоит
  галочка «сообщения о Раскате», есть результат за последние семь дней, а сегодняшнего нет (в тексте
  серия); на прогноз «Кто победит?» — за два часа до начала матча подписчику команды, который ещё
  не голосовал, по ближайшему матчу. Для этого бот открывает `state.db` своим соединением. Telegram
  отказался доставить — снимаем галочку `messages` (или подписку), больше не зовём.
- Напоминания уходят в свой час (19:00 накануне, 10:00 в день игры), но час можно и пропустить:
  выкладка, перезапуск, упавший туннель. Поэтому бот помнит в `reminded.json`, какое напоминание
  ушло и кому именно, и первые три часа догоняет пропущенное — тем, кто его не получил, по одному
  разу. Начавшийся матч не напоминает. Рассылку, где никто не получил сообщение (лёг туннель),
  повторяет до шести раз, проверяя раз в пять минут.
- «Too many requests» от Telegram (429) не теряет сообщение: бот ждёт столько, сколько просит
  Telegram (до двух минут), и дописывает. Сколько раз пришлось ждать — счётчик `retry_after` на пульте.
- Перед сервером бот жил на раннере GitHub («Запустить бота»). Это теперь только стенд: две
  копии одновременно ломают друг другу polling.

### Голы по табло — служба `clips` (ADR-030)

- `clips.py`, раз в 10 минут: сыгранные за три дня матчи с записью лиги (или ссылкой админа в `/replay`) — проход
  по записи (ffmpeg, yt-dlp), голы по табло трансляции. Секунды — в `live/clips.json`, API отдаёт
  `/api/live/clips.json`, задание Pages кладёт копию `clips.json`: «Повтор» точный у найденных голов без разметки
  админа. В `/replay` такие голы — ⏱ (встали часы) и 📺 (смена счёта на табло).
- Каждый ролик разбирается один раз; VK не отдал — до трёх попыток, ошибка — в `live/clips.json`. Длины записи VK
  ещё не знает (эфир идёт или запись обрабатывается) — служба её не разбирает (`wait`, в `/replay` — «Запись ещё не
  готова») и спрашивает снова раз в 20 минут до конца следующего дня: 06.10 разбор во время эфира дал кадр табло для
  разметки из заставки до матча.
- **Табло клуба-хозяина не размечено** (ADR-030, дополнение 06.10) — голов его домашних матчей служба не видит: ни
  секунд, ни превью, ни клипов. Кадр с сеткой лежит в `probe/grids/<клуб>.png` до разметки, в `live/clips.json` —
  `boards` (клуб → сколько матчей ждут, последний матч, кадр). Бот один раз присылает кадр `ADMIN_IDS` файлом
  (`grids.json` бота помнит, кому ушло). Что делать: переслать файл в сессию Claude — «разметь табло `<клуб>` в
  boards.json по grid.png»; после слияния и выкладки служба сама переберёт все матчи клуба с записью. На пульте —
  плитка «матчей ждут разметки табло».
- Низкий приоритет (`Nice`, `CPUQuota`, idle-диск). Кадры прохода — `probe/scoreboard/`, держатся три дня.
- Пробники руками — от того же пользователя, что служба: `sudo -u rhl venv/bin/python tools/probe_scoreboard.py …`.
  Папки от root служба не перезапишет (`PermissionError`, 05.10); `rhl-update` возвращает `probe/` пользователю `rhl`.
- Табло размечено (06.10): Калуга, Ростов, Рязань-ВДВ, Тверичи, Протон, Красная машина, Факел Ямал, Белгород,
  Дизелист — 9 клубов из 26. У «Белгорода» и «Дизелиста» — тот же шаблон табло, что у «Рязань-ВДВ» (красная плашка
  слева вверху), разметка одна: сверено по кадрам их матчей 06.10. Новому клубу сначала стоит примерить её.
  У «Факел Ямала» табло без плашки — буквы прямо поверх картинки, красные цифры счёта в сером плохо видны на светлом
  льду: секунд «сами» у него будет меньше, чем у клубов с плашкой.
- Цифры счёта служба не читает, а сравнивает картинки в клетке (07.10, этап 0.2 плана): новая картинка — новая цифра,
  уже виденная — старое табло (повтор гола, обзор голов в перерыве и после матча), строка, подсвеченная белым, — та же
  цифра. До этого у шаблона «Рязань-ВДВ» подсветка и обзоры считались сменами счёта, цепочка цифр рвалась, и голы
  отбрасывались. Картинки цифры почти не видно (прозрачные цифры «Факел Ямала») — смены по пикселям, как раньше.
  «Табло на экране» — по частому виду названия хозяев; если такой образец видит табло реже чем в 15% записи (долгий
  неподвижный фон, копия «Протона» 04.10), — по самой частой картинке названия (07.10, вечер). Превью ищут остановки
  часов с образцом всей записи.
- Нужен ffmpeg (`rhl-update` ставит сам) и yt-dlp (`requirements.txt`). VK сменил плеер — `venv/bin/pip install -U yt-dlp`.
- **Клипы (шаг 6).** У гола с точной секундой (админ, часы, табло) и протоколом служба режет клип 30 с (20 до гола,
  10 после, 720p, знак «Навигатор РХЛ» и «Источник: РХЛ») и обложку и кладёт их в бакет `rhl-clips` Timeweb Cloud
  (`s3.py`, ключи `CLIPS_S3_*` в `/etc/rhl/bot.env`). Адреса — в `live/clips.json` у матча в `clips`; сборка ставит
  `clip` у гола, мини-апп играет его под строкой гола. Скрыт по просьбе автор или ассистент, гол отменён в
  протоколе — клип удаляется из бакета на следующем проходе. Без ключей клипы не режутся. `live/clips.json` — в бэкапе:
  по нему служба знает, какие файлы лежат в бакете.
- **Клипы стёрты 06.10, нарезка на паузе** (ADR-030, дополнение 06.10, ночь): служба один раз стёрла все клипы из
  бакета и `live/clips.json` (копия — `live/clips.before-wipe-2026-10-06.json`) и не режет новые, пока в
  `/etc/rhl/bot.env` нет `CLIPS_CUT=on`. Разбор табло, превью и «Повтор» ссылкой VK работают; в
  `status/clips.json` — `info.cut`. Пауза держится, пока не выбрана новая схема секунды гола.
- **Превью голов (шаг 3).** Гол, который табло узнало, но без секунды, — служба ставит превью службе `cuts` (две
  минуты записи до смены счёта, 480p со знаком лиги; до 07.10 резала сама, 360p) и ищет моменты, когда вставали часы. Бот раз в минуту (9:00–23:00, до четырёх за раз) присылает
  превью `ADMIN_IDS` и `PREVIEW_IDS` (помощники: только превью, без тревог и `/replay`) с кнопками «Гол на 0:47» и
  «Другое время». Ответ — опора в `live/replays.json`, как время из `/replay`; у всех, кому ушло превью, подпись
  меняется на «✅». Что ушло — `previews.json` бота (четыре дня). Матч, где у каждого гола есть секунда или превью,
  в напоминании идёт строкой «Ждут превью», а не «Без превью». Гол, которого табло не нашло вовсе (табло убирали на
  минуты), превью не получает: где он в записи, служба не знает (06.10 пробовали угадывать по времени сайта лиги —
  в пятиминутных превью гола не было, ADR-030, дополнение 06.10, вечер). Такой матч — строкой «Без превью» в
  вечернем напоминании, время гола — в `/replay`. Превью, на которое отвечать уже не нужно (секунда нашлась иначе,
  служба превью отозвала, у гола другое окно), бот сам удаляет из чатов, старше 48 часов — снимает кнопки.
- **Повтор у каждого гола (ADR-031).** Гол со сменой счёта на табло, но без точной секунды сразу получает примерный
  повтор — с 100 секунд до смены (оператор меняет счёт через 0–90 с после гола). Счёт хода часов: от гола с точной
  секундой служба идёт по записи кадр в секунду и находит соседние голы периода по протоколу — 🕐 в `/replay`;
  пересчитывает, когда админ ответил на превью. Нет записи лиги — ролик VK из «Смотреть» поста клуба: по нему только
  повтор, клипы — из записи лиги и ссылки админа. Гол берётся, только если картинки цифр в клетке идут цепочкой от «0»
  (`verify_digits`); отброшенные — с причиной в разборе.
- **Пометки админа.** Под превью — «⚠️ Гола тут нет — табло сбилось», в `/replay` у гола — «🚫 Гола нет в записи» и
  «⚠️ Повтор не тот — табло сбилось». «Табло сбилось» снимает секунды табло у гола и у следующих голов той же команды.
  Пометки — в `live/replays.json` (`absent`, `wrong`).
- **Разбор покрытия.** У каждого сыгранного матча — сколько голов с повтором и почему не у всех (`coverage` в
  `live/clips.json`): нет записи, ждёт разбора, VK не отдал (с текстом ошибки), табло не размечено, табло не нашло голы
  (с причинами). Вечером бот присылает его админам, строка — в заголовке `/replay`, числа — на пульте.
- **Пульт (шаг 8).** После каждого матча и прохода служба пишет `status/clips.json`: пульс, отдал ли VK запись
  (`vk_ok`, `vk_fail`, последняя ошибка) и снимок каталога голов сезона — голов в матчах с записью лиги, с точной
  секундой (сами и админ), клипов, ждут превью, матчей без записи лиги, матчей и клубов без разметки табло, голов
  табло, которых нет в протоколе, и покрытие повторами: матчей с повтором у всех голов, без единого, голов с повтором,
  точных по ходу часов.
  Тревоги: служба молчит дольше часа; VK за день трижды не отдал запись и ни разу не отдал (лечит новый yt-dlp).

### Видео для админов — служба `cuts` (ADR-036)

- `cuts.py` вырезает кусок записи матча в mp4 — то, что админ или помощник смотрит в Telegram вместо ссылки VK.
  Задания — таблица `cut_jobs` в `state.db` (`cutjobs.py`): ролик, окно (начало и длина в секундах записи), вид,
  статус, файл и его размеры. Одно окно одного ролика — одно задание: попросили снова — то же задание и тот же файл.
- Кто ставит: служба `clips` — превью голов без секунды (бот пришлёт, когда файл готов) и после каждого прохода
  заготовки всего, что ждёт человека, у матчей последних двух дней: обе версии спора по отметке (30 с по отметке и
  30 с или окно до смены счёта по табло) и 30 с вокруг точной секунды с одним свидетелем (табло без отметки или
  отметка, которую нечем проверить). Дальше (этап 1.2 плана) — бот по запросу, срочно.
- Порядок: сначала ждёт человек, потом превью, потом заготовки; по одному. Не вышло — ещё раз через минуту и через
  десять, всего три попытки. Дальше заготовка остаётся ошибкой; превью `clips` просит снова каждый проход, и через два
  часа оно идёт на новый круг (VK лечат новым yt-dlp — превью не должно пропасть); человек, попросивший окно снова,
  запускает его сразу. Задание «в работе» дольше 30 минут (служба упала посреди него) берётся снова.
- Видео — 480p (та же запись, по которой `clips` считала секунды), H.264, `+faststart`, со знаком «Навигатор РХЛ» и
  «Источник: РХЛ». Перекодируем, поэтому нулевая секунда видео — ровно начало окна: «Гол на 0:47» — это начало плюс
  47 с. 30 с — около 2 МБ и 3–5 с работы, две минуты — около 8 МБ и 10–20 с.
- Адрес потока VK (yt-dlp) — один на ролик на 25 минут: кусок за куском одного матча не спрашивают VK заново.
  Защиту не обходим (ADR-012).
- Файлы — `media/cuts/<номер задания>.mp4`, задания и файлы живут три дня с последней просьбы, чистит служба раз в
  час. Id людей в `cut_jobs` нет.
- Приоритет ниже бота, `live` и `api`, но выше `clips` (`Nice=10`): видео ждёт человек, разбор подождёт.
- Пульт: `status/cuts.json` — пульс раз в минуту, сколько вырезано и не вышло за день, последняя ошибка, очередь.
  Тревоги: служба молчит дольше 20 минут (одно видео — до двух заходов по 5 минут); за день три видео не
  вырезались, и после них ни одно не вышло. Окно за концом записи и удалённая запись — ошибка сразу, без повторов.

### Пульт админа (ADR-021)

- Страница `admin.html` рядом с мини-аппом. Открывается из бота: `/admin` → «Открыть пульт». Пускает
  только Telegram id из `ADMIN_IDS` в `/etc/rhl/bot.env`; не-админу `/admin` пишет его id — так
  владелец узнаёт свой. После правки `ADMIN_IDS` — `systemctl restart bot api`.
- Наверху — «Всё работает» или список проблем. Дальше: службы (`systemctl show`), Telegram через
  туннель, сборки GitHub, свежесть `league.json` и `live/`, источники, соль «Раската», диск; аудитория —
  подписчики по командам, «Старт» по ссылкам, открытия мини-аппа, платформы, за кого болеют,
  «Возвращаются ли» (новые и вернувшиеся сегодня, возврат на следующий день и через неделю, уснувшие);
  рассылки; «Раскат» и «Кто победит?» по дням.
- Удержание считается по `admin_fans` в `state.db` — три числа на человека (когда пришёл, когда был
  последний раз, сколько дней заходил). Дневной журнал id (`admin_seen`) как и раньше живёт один
  день, воронок по людям нет (ADR-021 и его дополнение от 04.10).
- Откуда числа: бот раз в минуту пишет `status/bot.json` (пульс, `getMe` через туннель, счётчики за
  день), служба `pages` раз в 15 минут — `status/pages.json` (итоги заданий Actions тем же
  `PAGES_TOKEN`), служба `clips` после каждого матча — `status/clips.json` (пульс, VK, каталог голов), служба
  `cuts` раз в минуту — `status/cuts.json` (пульс, видео за день, очередь),
  сервер API — открытия в `state.db`. Только числа: ни id, ни имён на пульте нет.
- Пульт только показывает: перезапуска и рассылок с него нет.
- Тревоги (ADR-022): служба `api` раз в две минуты пишет список проблем в `status/alerts.json`, бот
  раз в минуту его читает и присылает `ADMIN_IDS`: новое — сразу, та же поломка — не чаще раза в
  час, «посмотреть» — один раз, пропало — «починилось». Ночью (23:00–9:00) молчит. Нет файла или он
  старше 10 минут — бот пишет, что молчит сама служба `api`. Умер бот целиком — тревогу отправить
  некому: это закрывает только внешняя проверка `/api/health`, её пока нет.

### Выкладка

- Слияние в `main` запускает задание **«Выложить бота на сервер»** (`deploy.yml`). Задание по ssh
  запускает на сервере `rhl-update`: `git reset --hard origin/main`, pip, установка и перезапуск
  служб `bot`, `live`, `api`, `pages`, `clips`, `cuts` из `deploy/` и проверка каждой (у `api` — `/api/health`). Службу, чьего
  файла кода ещё нет в `main`, выкладка пропускает с сообщением. Правки только в `webapp/`,
  `docs/`, `art/`, `stickers/` и `*.md` служб не перезапускают.
- `rhl-update` обновляет сам себя: новая `deploy/update.sh` в `main` ставится и сразу продолжает
  выкладку. Старая копия, поставленная до служб `api` и `live`, этого не умела — её один раз
  заменяет `deploy/https.sh`.
- Ключ выкладки на сервере умеет одно — запустить `rhl-update`.

## Что делать, если

| Что видно | Команда на сервере |
| --- | --- |
| Бот молчит | `systemctl status bot tg-tunnel`, `journalctl -u bot -n 50` |
| В журнале `Request timeout error` | Лёг туннель: `journalctl -u tg-tunnel -n 30`, `systemctl restart tg-tunnel` |
| В журнале `Conflict: terminated by other getUpdates` | Где-то вторая копия бота — отменить «Запустить бота» в Actions |
| Выкладка красная, `error in libcrypto` | Секрет `DEPLOY_SSH_KEY` вставлен с ошибкой: весь блок BEGIN…END заново |
| Нужно выложить руками | `rhl-update` |
| Мини-апп со старыми данными | Actions → «Мини-апп» → лог. Обычно r-hockey не ответил: следующий час соберёт |
| Зачёт «не отвечает», прогнозов нет | `systemctl status api caddy`, `journalctl -u api -n 50`, `curl -s 127.0.0.1:8080/api/health` |
| Зачёт «временно выключен» | Опубликованный расклад дня не читается: `curl -s 127.0.0.1:8080/api/health` → `raskat.note`. Если там про соль — выровнять `RASKAT_SALT` в `/etc/rhl/bot.env` под секрет Pages, `systemctl restart api` |
| HTTPS не открывается, сертификат | `journalctl -u caddy -n 50`; открыты ли 80 и 443 у хостинга и в `ufw status`; повторить `bash /opt/rhl/deploy/https.sh` |
| Живого счёта нет | `systemctl status live`, `journalctl -u live -n 50`, `ls -l /opt/rhl/live` |
| Превью голов не приходят, на пульте «Нарезка видео не выходит» | `journalctl -u cuts -n 80` — у каждого невышедшего задания строка с матчем, голом и ошибкой (она же — в `cut_jobs`); VK не отдаёт поток — `sudo -u rhl /opt/rhl/venv/bin/pip install -U yt-dlp`, `systemctl restart cuts clips` |
| Голы по табло не находятся | `journalctl -u clips -n 80`; ошибка матча — в `/opt/rhl/live/clips.json`; VK не отдаёт поток — `sudo -u rhl /opt/rhl/venv/bin/pip install -U yt-dlp`, `systemctl restart clips` |
| Мини-апп открывается с 404 «There isn't a GitHub Pages site here» | Адрес Pages сменился (репозиторий переименовали: `bogdanov` → `RHL-BOT`). `WEBAPP_URL=https://arpicasso.github.io/RHL-BOT/` в `/etc/rhl/bot.env`, `systemctl restart bot api`, и тот же адрес в @BotFather → `/myapps` → Edit Web App URL |
| Тревоги не приходят | `ADMIN_IDS` в `/etc/rhl/bot.env` (после правки — `systemctl restart bot api`), `ls -l /opt/rhl/status/alerts.json` (должен быть свежее двух минут), `journalctl -u api -n 30` |
| Тревоги приходят об одном и том же | Причина не ушла — смотри её на пульте. Напоминание раз в час на причину так и задумано |
| Пульт: «Нет доступа» | Свой id — боту `/admin`; вписать в `ADMIN_IDS` в `/etc/rhl/bot.env`, `systemctl restart bot api` |
| Пропало всё: подписки, зачёт, прогнозы | Из бэкапа: `systemctl stop bot api`, `cp /var/backups/rhl/state-ГГГГ-ММ-ДД.db /opt/rhl/state.db`, то же для нужных `*-ГГГГ-ММ-ДД.json` (имя — без даты, например `subscribers.json`), `chown rhl:rhl /opt/rhl/state.db /opt/rhl/*.json`, `systemctl start bot api` |
| Бэкапа за сегодня нет | `systemctl status backup.timer`, `journalctl -u backup -n 30`; руками — `systemctl start backup` |
| Пульт: «Бот не пишет пульс» | `ls -l /opt/rhl/status`; нет каталога — `rhl-update` его создаст |

## Чего пока нет

- **Бэкапа вне сервера.** Ночной бэкап есть (таймер `backup` → `/var/backups/rhl`, 14 дней), и он
  спасает от испорченной базы, неудачной выкладки и случайного `rm`. Но лежит он на том же диске:
  умрёт сервер — умрёт и он. Куда возить копию (чужой сервер по `scp`, S3, чат с ботом), решаем
  отдельно: в `state.db` есть Telegram id, и место для него — это решение о персональных данных.
- **Сайта РХЛ**: календарь — предварительный с r-hockey (`official: false`), протоколов
  и лидеров 2026/27 нет.
- **Живого счёта** (ADR-012): опрос источников с этого сервера — следующий шаг.
- **Внешней проверки.** Тревоги (ADR-022) приходят от бота, поэтому смерть самого бота или всего
  сервера он сообщить не может. Нужен чужой монитор, который дёргает `/api/health` и пишет при
  молчании.
