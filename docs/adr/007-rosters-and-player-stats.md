# ADR-007. Составы команд и статистика игроков

Статус: принято, 25.09.2026 — запрос владельца продукта. Реализация ждёт открытия `rhl.fhr.ru`

## Контекст

В паспорте болельщика сейчас только клуб и три цифры сезона. Болельщик хочет видеть своих:
кто в составе на сезон, кто сколько забил и отдал. В детско-юношеской лиге болеют родители и
друзья игроков — для них фамилия в составе важнее таблицы.

Что есть в источниках (проверено 25.09.2026):

- На `nmhl.fhr.ru` у каждого клуба в турнире есть страница `/stat/players/<турнир>/all/<клуб>/`:
  полевые игроки и вратари, номер, игры, голы, передачи, штраф, у вратарей — пропущенные,
  процент отражённых, «сухие» игры. Id клуба в турнире берётся из фильтра календаря
  (`league.parse_club_ids` уже это умеет). `rhl.fhr.ru` на том же движке, но пока закрыт
- В протоколе каждого матча (ADR-001) уже есть авторы голов и передач с номерами
- На `r-hockey.ru` есть страница «Состав на текущий сезон», но список игроков рисуется
  скриптом — без браузера его не достать. Для сверки, не как источник

Вопрос из `ARCHITECTURE.md` «даст ли клуб составы и согласие» снимается частично: состав и
статистику публикует сама лига, мы их только показываем со ссылкой на источник.

## Решение

1. **Источник — страница статистики клуба на сайте лиги.** Она же и состав: кто сыграл хотя бы
   один матч, тот в составе. Пока `rhl.fhr.ru` закрыт, составов 2026/27 у нас нет, и экран
   честно пишет «Состав появится после первого тура». Составы с агрегаторов не показываем
2. **`league.py --players`** — скачать страницы статистики всех 26 клубов, по одной в секунду.
   Результат — `players.json`: id турнира → id команды → игроки. Обновляется тем же заданием,
   что и протоколы, после каждого игрового дня
3. **В `league.json` — только составы и строка статистики игрока**: номер, фамилия и имя,
   амплуа, И, Ш, А, О, Штр; у вратарей — И, ПШ, %ОБ, И«0». Больше ничего о человеке не берём:
   ни даты рождения, ни фото, ни ссылок на соцсети
4. **Экран «Я»**: под паспортом — «Состав» любимой команды, три группы (вратари, защитники,
   нападающие; если амплуа нет в источнике — вратари и полевые). Сверху — три лидера команды
   по очкам. Нажатие на игрока — карточка: номер, строка статистики, голы по матчам из
   протоколов
5. **Та же карточка у соперника**: из карточки матча — «Составы» обеих команд
6. **Удаление по просьбе** (правило 4 `CLAUDE.md`): `hidden_players.json` в git — список id
   игроков, которых не показываем. Пополняется по обращению игрока, родителей или клуба
   за один коммит

## Решённые вопросы

- **Клубы предупреждены** (25.09.2026), что мы показываем фамилии и статистику игроков,
  которые публикует лига. Игрокам РХЛ 16–19 лет, поэтому удаление по просьбе (пункт 6)
  обязательно
- **Статистику только по протоколам не показываем.** Ждём открытия сайта РХЛ и берём составы
  и статистику со страниц клубов. До этого экран пишет «Состав появится после первого тура»

## Последствия

- Каждый игровой день — ещё 26 запросов к сайту лиги; при паузе в секунду это полминуты
- `league.json` вырастет примерно на 60 КБ (26 × ~30 игроков). Если первый запуск заметно
  замедлится — составы уедут в отдельный файл по образцу `h2h.json` (ADR-006)
- Фэнтези и голосование «лучший игрок матча» из `ARCHITECTURE.md` становятся возможны после
  этого шага

## Дополнение, 27.09.2026: фэнтези «Звено» (ADR-014)

Правило «статистику только по протоколам не показываем» относится к строке статистики игрока в
составах. Очки «Звена» считаются по протоколам лиги (ADR-001), и это не противоречие: это правило
игры внутри «Звена», а не статистика игрока. Вне «Звена» очков и стоимости нет — ни в составах, ни
в карточке игрока, ни у лидеров. Строка статистики в составах по-прежнему берётся со страниц клубов
на сайте лиги. `hidden_players.json` действует и в «Звене»: скрытый игрок сразу уходит из пула.
