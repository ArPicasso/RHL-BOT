# ADR-020. «Кто победит?» — прогноз болельщиков на матч

Статус: принято, 03.10.2026 — запрос владельца продукта: «подогрев к матчам, чтобы болельщик
ощущал себя частью каждой команды РХЛ. Нужно больше взаимодействий». Сервер — ADR-019.

## Контекст

У мини-аппа нет ни одного действия болельщика вокруг настоящего матча: только смотреть. Лист
дня (ADR-015) и «Раскат» (ADR-018) удерживают, но ни то, ни другое не связано с игрой вечером.
У КХЛ и МХЛ подогрев — это голосование «кто победит» с долями трибуны и итог после матча.

Ограничения те же, что у «Раската» и фэнтези (ADR-014, ADR-018): подростковая аудитория и
244-ФЗ. Значит, никаких ставок, валюты, призов и коэффициентов.

## Решение

### 1. Механика

- У каждого матча лиги до его начала — два больших выбора с эмблемами: «Хозяева» и «Гости».
  Ничьей нет: в хоккее РХЛ победитель есть всегда (ОТ, буллиты)
- Голос один, его можно поменять до начала матча. С начала матча (время `start` или статус
  `live` в `live/*.json`) приём закрыт. Время неизвестно — приём открыт до конца дня матча по Москве
- После голоса — доли трибуны: «64% за „Рязань-ВДВ“ · 128 голосов». До своего голоса долей не
  видно: иначе все голосуют за большинство
- После матча — «Угадал» / «Не угадал» и личное число «угадано 5 из 8» с серией подряд. Итог
  матча — протокол лиги или `final` в `live/*.json`
- Никаких очков, мест, призов и таблицы людей: только своё число и доли трибуны. Таблицы
  «лучших прогнозистов» нет сознательно — это первый шаг к тотализатору

### 2. Где

- Мини-апп: карточка своего матча на «Главной», строки «Матчи дня в РХЛ» (компактно), карточка
  матча — сверху, до разбора
- Бот: в напоминании о матче — кнопка «Кто победит?» ведёт в карточку матча в мини-аппе. Голос
  только в мини-аппе: один вход, одна проверка `initData`

### 3. API (база `LIVE_API`, авторизация как у «Раската»: `Authorization: tma <initData>`)

| Метод и путь | Тело → ответ |
| --- | --- |
| `GET /predict/day/<дата>` | → `{"games": {"<ключ>": Tally}}`. Без авторизации `me` всегда `null` |
| `POST /predict/vote` | `{"key": "<ключ>", "pick": "home" \| "away"}` → `Tally`. 409 — приём закрыт |
| `GET /predict/me` | → `{"right": 5, "of": 8, "streak": 2}` |
| `DELETE /predict/me` | → `{}` — стирает все голоса болельщика |

```json
Tally {"home": 64, "away": 36, "votes": 128, "me": "home" | "away" | null,
       "open": true, "result": "home" | "away" | null}
```

- Ключ матча — `<дата>|<хозяева>|<гости>` (ADR-019, раздел 5). Сервер принимает голос только за
  матч, который есть в `live/<дата>.json`, `live/schedule.json` или опубликованном `league.json`
- `home`/`away` в `Tally` — проценты, целые, в сумме 100; при `votes == 0` оба 0. Пока болельщик
  не проголосовал, сервер отдаёт доли (мини-апп их прячет): так экран не ждёт второго запроса
- Хранится: id пользователя Telegram, ключ, выбор, время. Имени нет. `DELETE /predict/me` и
  `DELETE /raskat/me` — способ удаления (`CLAUDE.md`, правило 4)

### 4. Без сервера

`LIVE_API` пуст — блока «Кто победит?» нет вовсе. Голос на устройстве без долей трибуны — не
взаимодействие, а форма без ответа.

## Чего не делаем

- Не показываем коэффициенты и не связываем прогноз ни с чем денежным
- Не делаем таблицу людей по прогнозам и не раздаём призов
- Не шлём сообщений «твой прогноз не сбылся»

## Последствия

- `predict.py` — хранилище голосов в SQLite (`state.db`, рядом с зачётом «Раската»), `server.py`
  отдаёт его по HTTP
- В «Я» у болельщика появляется строка «Прогнозы: угадано 5 из 8»
