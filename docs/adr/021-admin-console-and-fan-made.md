# ADR-021. Пульт админа и пометка «приложение болельщиков»

Статус: принято, 03.10.2026. Запрос владельца продукта перед запуском на большую аудиторию:
«трекеры всей информации, которая может быть полезной для админов, состояния системы. И пару
указателей, что это приложение для болельщиков от болельщиков, а не официальное РХЛ».
Канал выбран владельцем: веб-страница. Трекеры — все четыре группы: здоровье системы,
аудитория, рассылки, игры.

## Контекст

В `docs/SYSTEM.md` прямо написано: «Мониторинга нет: о падении бота никто не узнает, пока
не заметит». Сейчас о состоянии можно узнать только из SSH: `journalctl`, `ls -l live/`,
`curl /api/health`, лог задания Pages в Actions. О людях не знаем ничего, кроме размера
`subscribers.json`: ни сколько открывают мини-апп, ни сколько ушло напоминаний, ни сколько
человек заблокировали бота.

Кусочки здоровья уже есть, но разбросаны:
- `/api/health` — жив ли API, сошлась ли соль «Раската», когда обновлялось живое;
- `live/sources.json` — у каждого живого источника время удачи, ошибки подряд, заметка
  (ADR-012, раздел 6);
- `league.json` на Pages — поле `updated`, время последней сборки;
- служба `pages` знает, запустилась ли сборка, но никому не говорит.

Вторая проблема — бот называет себя «Бот Первенства России U21», а в мини-аппе эмблемы
лиги и клубов. Человек со стороны легко примет нас за официальное приложение лиги. Нам это
вредно: жалобы на судейство и билеты пойдут к нам, а лига или клуб могут спросить, почему
мы говорим от их имени (`docs/ARCHITECTURE.md`, граница ответственности).

## Решение

### 1. Пульт — страница `webapp/admin.html`

- Отдельная страница рядом с мини-аппом на Pages, свой `admin.js` и `admin.css`. В `app.js`
  её нет: пульт не грузится у болельщиков и не мешает им
- Открывается только из Telegram: бот на `/admin` присылает кнопку Web App на
  `<WEBAPP_URL>admin.html`. Вне Telegram подписи `initData` нет, и страница честно пишет
  «открой из бота»
- Данные — `GET <LIVE_API>/admin/status` на VPS. Доступ — подпись `initData`, как у зачёта, и
  Telegram id из списка `ADMIN_IDS` (`/etc/rhl/bot.env`, через запятую). Чужой id → 403, пустой
  список → 403 с подсказкой, куда вписать. `/admin` у не-админа отвечает его id и тем, куда его
  вписать: так владелец узнаёт свой id в первый раз
- Страница перечитывает статус раз в минуту, пока открыта. Наверху — сводка «Всё работает» или
  «Проблем: N» со списком: так за пять секунд видно, надо ли что-то делать
- Пульт только показывает. Кнопок «перезапустить», «разослать» и правки данных нет: каждая такая
  кнопка — дыра, если подпись или список админов однажды утекут

### 2. Что на пульте

**Здоровье системы** — то, что обычно смотрят по SSH:

| Что | Откуда |
| --- | --- |
| Службы `bot`, `live`, `api`, `pages`, `tg-tunnel`, `caddy`: состояние, с какого времени, сколько раз systemd перезапускал после падения | `systemctl show` с сервера API |
| Telegram: когда бот последний раз достучался до Bot API, ошибка | пульс бота `status/bot.json`: раз в минуту `getMe` через туннель |
| Сборки GitHub: «Мини-апп», «Выложить бота», «Тесты» — последний итог, последняя удачная, неудачных за сутки | служба `pages` раз в 15 минут читает список запусков Actions тем же `PAGES_TOKEN` → `status/pages.json` |
| Данные на Pages: когда собран `league.json` | `updated` опубликованного `league.json` |
| Живое: когда обновлялось, источники и ошибки подряд | `live/today.json`, `live/sources.json` |
| «Раскат»: соль, зачёт включён ли | то же, что в `/api/health` |
| Диск: свободно, размер `state.db` | сервер API |

**Аудитория** — только счётчики за день, без списков людей:
- подписчики на напоминания: всего и по командам (читается `subscribers.json`);
- за день: `/start` всего и по ссылкам (`today`, `remind`, команда, …), новые подписки, «Выключить»,
  заблокировали бота;
- открыли мини-апп: уникальные люди за день, платформы (`ios`, `android`, `tdesktop`, …) и за
  кого они болеют. Считает сервер API по запросу `POST /api/seen`, который мини-апп шлёт один раз
  за открытие, если открыт в Telegram и `LIVE_API` задан.

**Рассылки**: за день — напоминаний и финалов ушло, не ушло; последние десять рассылок — что, когда,
сколько, за сколько секунд. Ошибки бота за день — число и шаблон последней (`send to %s failed`)
без подставленных значений: в них бывают chat_id.

**Игры**: «Раскат» — сколько результатов сегодня и за семь дней, всего игроков в зачёте;
«Кто победит?» — голосов и голосовавших за день, самые обсуждаемые матчи дня.

### 3. Как службы отдают счётчики

- Новый модуль `admin.py`, только stdlib: `Tracker` копит счётчики по дням (МСК, держит 35 дней)
  и пишет `status/<служба>.json` атомарно; `collect` и `problems` собирают пульт и сводку
  проблем. Его зовут бот, `pages_kick.py` и сервер API
- Каталог `/opt/rhl/status/` (не в git). Бот пишет `bot.json`, служба `pages` — `pages.json`.
  Каталог создаёт `rhl-update`, службе `pages` добавлен `ReadWritePaths` только на него
- Сервер API держит счётчики открытий в своей SQLite (`admin_seen`, `admin_counts`)

### 4. Пороги «проблемы»

| Проблема | Порог |
| --- | --- |
| Служба не `active` | сразу |
| Служба перезапускалась после падения | `NRestarts` > 0 — предупреждение |
| Пульс бота | старше 3 минут |
| Telegram недоступен | последний `getMe` неудачный |
| Сборка «Мини-апп» | последняя удачная старше 90 минут днём (с 7:00 до 2:00 МСК) |
| `league.json` | собран дольше 2 часов назад |
| Выложить бота | последний запуск красный |
| Живой источник | 3 ошибки подряд |
| Зачёт «Раската» | выключен |
| Диск | свободно меньше 1 ГБ |

### 5. Персональные данные (`CLAUDE.md`, правило 4)

- Счётчики по дням не про человека: ни id, ни имён в `status/` и `admin_counts` нет
- `admin_seen` — id и день, только чтобы не считать человека дважды за день. Строки старше
  вчерашнего дня сервер стирает сам. Кнопки «Удалить мои раскаты» и «Удалить прогнозы» стирают
  и их
- Пульт не показывает ни одного id и ни одного имени, кроме имени самого админа в шапке

### 6. «Сделано болельщиками»

Пометка в четырёх местах, коротко и без извинений:

1. **Описание бота** (видно до «Старт» и в профиле): «Неофициальный бот болельщиков…» и
   последней строкой «Сделан болельщиками, не связан с РХЛ и ФХР»
2. **Приветствие бота** `/start`: последней строкой «Приложение болельщиков для болельщиков —
   не официальное приложение РХЛ»
3. **Мини-апп, первый экран** («За кого болеете?») и **подвал каждой вкладки**: «Сделано
   болельщиками для болельщиков · не официальное приложение РХЛ». Нажатие открывает лист
   «О приложении»
4. **Лист «О приложении»** — ещё и строкой в «Я → Настройки»: кто мы, что мы не связаны с РХЛ,
   ФХР и клубами, откуда данные и что при расхождении права лига, чьи эмблемы, что ставок и
   букмекеров здесь нет. Официальный источник — ссылка на `rhl.fhr.ru`

## Чего не делаем

- Тревоги в Telegram и утреннюю сводку — пока нет. Пульт уже считает проблемы (`problems`):
  тревога — это тот же список, разосланный ботом, следующим шагом
- Аналитику по людям: кто что нажал, воронки по id. Только счётчики
- Действия с пульта: перезапуск, рассылки, правку данных

## Последствия

- `admin.py`, `webapp/admin.html`, `admin.js`, `admin.css`, мок `webapp/data/admin/mock/status.json`
  (`admin.html?admin_mock=1`)
- `server.py`: `GET /api/admin/status`, `POST /api/seen`; `bot.py`: счётчики, пульс, `/admin`
- `pages_kick.py` раз в 15 минут читает список запусков Actions (тот же токен, право Actions: Read)
- Новые переменные `ADMIN_IDS`, `STATUS_DIR` в `/etc/rhl/bot.env`
- Задание Pages подставляет `LIVE_API` и в `admin.html`

## Дополнение 04.10.2026: возвращаются ли люди

Разбор перед запуском на сотню болельщиков показал дыру в пульте: по нему видно, **сколько**
человек открыло мини-апп сегодня, но нельзя сказать, **те же это люди или каждый день новые**. Для
удержания это и есть главный вопрос: неизвестно, что чинить — приход или возврат, и непонятно,
помогли ли зовы (ADR-023) и голы (ADR-024).

Поэтому в `state.db` появляется `admin_fans` — **три числа на человека**: когда пришёл впервые
(`first`), когда был в последний раз (`last`), сколько всего дней заходил (`days`). Из них считаются
и показываются на пульте, в карточке «Возвращаются ли»:

| Строка | Что значит |
| --- | --- |
| Сегодня: N новых · M вернулись | `first = сегодня` и `last = сегодня при first < сегодня` |
| На следующий день | из когорты `first = вчера` — у кого `last = сегодня` |
| Через 7 дней | из когорты `first = неделю назад` — у кого `last > first` |
| Уснули | `last` от трёх дней до пяти недель назад |
| Знаем всего | сколько людей вообще открывало мини-апп |

Решение выше («`admin_seen` — id и день, строки старше вчерашнего сервер стирает сам») **остаётся
в силе**: дневной журнал id по-прежнему живёт один день, и воронку «кто что нажал» из `admin_fans`
не собрать — в нём нет ни одного события, только три даты. Запрет из «Чего не делаем» (аналитика по
людям) этим не нарушается: наружу по-прежнему уходят только числа, без id и имён.

`forget` (ADR-018, раздел 3.9) стирает строку `admin_fans` вместе с остальным: кнопка «удалить мои
данные» остаётся полной (CLAUDE.md, правило 4).
