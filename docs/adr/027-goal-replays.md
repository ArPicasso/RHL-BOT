# ADR-027. Повторы голов: запись трансляции лиги с секунды гола

Статус: принято, 04.10.2026. Просьба владельца: у гола в разборе матча — кнопка «Повтор».

## Контекст

- **Отдельных роликов голов нет.** Лига на вкладке «Видео» матч-центра вставляет всю трансляцию:
  плеер VK `video_ext.php?oid=-X&id=Y` (ADR-019, раздел 7; снимки 03.10). Нарезок голов нет ни на сайте,
  ни в каналах клубов. Резать видео сами не будем: это чужая запись и тяжёлая обработка.
- **VK открывает ролик с нужной секунды**: `https://vk.com/video-X_Y?t=14m32s`. Такую же ссылку VK даёт
  кнопкой «Копировать ссылку с текущим временем».
- **По часам матча секунду записи не посчитать.** Время в хоккее останавливают: 20 минут периода — это
  полчаса и больше. Пересчёт «12:34 во 2-м периоде → минута записи» ошибается на минуты.
- **Зато есть время по часам.** Служба `live` смотрит страницу матча раз в 30 секунд и пишет `at`:
  когда сменился счёт (ADR-019, раздел 5). Разница по часам между двумя голами равна разнице между ними
  в записи, если трансляция шла без разрывов. Голы узнаются по счёту после гола: «1:0», «1:1» —
  как в протоколе.
- **Нет одной связки «секунда записи ↔ время по часам».** Когда началась трансляция, мы не знаем:
  VK с наших машин не проверить (с раннера GitHub закрыт), а начало эфира у клубов плавает на 5–15 минут.

## Решение

1. **Опору ставит админ, одну на матч.** В боте `/replay` (только `ADMIN_IDS`, в меню её нет):
   матчи последних трёх дней, где служба видела голы → голы матча → админ нажимает гол, ставит запись
   на момент, когда шайба в воротах, и присылает ссылку VK «с текущим временем». Ролик уже известен —
   хватит времени записи «14:32».
2. **Остальное считает `replay.py`.** У отмеченного гола повтор точный: за `EXACT_LEAD` = 10 секунд,
   видно атаку. Остальные — от ближайшей по часам опоры: её секунда плюс разница по часам, минус
   `GUESS_LEAD` = 45 секунд (30 — шаг опроса, 15 — атака). Болельщик попадает за 15–75 секунд до гола.
   Опор может быть сколько угодно: трансляция прервалась в перерыве — отмечают по голу в каждом периоде.
   Новая ссылка на другой ролик сбрасывает опоры матча.
3. **Ответ бота — уже проверка.** После каждой ссылки бот присылает все голы со ссылками: ✅ — отмечен,
   ≈ — посчитан. Админ тут же жмёт и смотрит; расчётный мимо — отмечает этот гол сам.
4. **Без времени по часам повтора нет.** Голы, которые служба заметила после паузы опроса дольше
   5 минут, помечены `late`: их `at` — не время гола. Голы без счёта (счёт вырос у обеих сторон
   между опросами) не узнать в протоколе. Такие можно только отметить руками.
5. **Где лежит.** `live/replays.json` на сервере (пишет бот, в бэкапе: это ручная работа):
   `{"updated", "games": {"<дата>|<хозяева>|<гости>": {"video", "anchors": {"1:0": 1800},
   "goals": [{"score", "team", "t", "exact", "url"}], "updated"}}}`. Сервер API отдаёт его как
   `/api/live/replays.json`, задание Pages кладёт копию рядом со `schedule.json`, `build_data.py`
   ставит `replay` у гола в `league.json` по ключу матча и счёту (буллиты не размечаем, только ссылки
   `https://vk.com/video…?t=…`). В мини-аппе под автором гола — кнопка «Повтор» (`data-out`, как «Смотреть»).

## Что не делаем и почему

- **Не угадываем начало трансляции** по расписанию: ошибка в минуты хуже, чем нет кнопки.
- **Не пересчитываем по часам матча**: см. контекст, время останавливают.
- **Не шлём повтор в пуше гола (ADR-024)**: пуш уходит по ходу матча, а запись и опора появляются после.

## Персональные данные

Нет: в `replays.json` только ссылки на ролик и секунды. Кто из админов отметил, не храним.

## Как проверить

1. После матча, где служба `live` видела голы: `/replay` → матч → гол → ссылка VK с временем.
2. Бот отвечает списком голов: ✅ у отмеченного, ≈ у остальных. Ссылки открываются в VK с нужного места.
3. Через одну сборку Pages (до 15 минут) в разборе матча под голами — «Повтор».

Расчётные часто начинаются уже после гола — значит, сайт лиги отмечает голы с разной задержкой,
и запас `GUESS_LEAD` в `replay.py` надо увеличить. Начинаются слишком рано — уменьшить.

## Дальше: без ручной опоры (04.10.2026)

Ручная опора нужна, пока неизвестно начало записи по часам. Его может знать сам VK: публичная страница
ролика и плеер, вероятно, несут дату эфира и длительность, а `video.get` API — поля `date`, `duration`.
`tools/probe_vk.py` на сервере сравнивает каждую метку VK с началом записи по опорам админа. Поле,
которое на нескольких матчах сходится с опорой в пределах ±30 секунд, станет автоматической опорой,
а ручная останется поправкой. Не сойдётся ни одно — остаёмся на ручной.
