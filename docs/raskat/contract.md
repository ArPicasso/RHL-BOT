# «Раскат» — контракт реализации

Игра-головоломка вкладки «Раскат» (ADR-018): одна шайба проходит весь лёд и задевает номера
звена по порядку. Правила механики, соревнования и подачи — в ADR-018, интерфейс — в
`DESIGN.md` → «Раскат». Здесь только стыки: кто что пишет, формат файлов, функции движка,
API сервера, бот.

Три части живут отдельно и сходятся по этому файлу:

| Часть | Пишет | Читает |
| --- | --- | --- |
| Движок `raskat/` | расклад дня, проверку пути, очки, зачёты | движок зависит только от stdlib |
| Сборка `build_raskat.py` | `webapp/data/raskat/*.json` | движок |
| Мини-апп `webapp/raskat.js` | ничего, только играет | опубликованные файлы и API сервера |
| Сервер `server.py`, хранилище `raskat_store.py` | результаты, зачёты, серии (`state.db`) | движок как библиотеку, опубликованный файл дня для сверки соли |
| Бот `bot.py` | лист ожидания, напоминание про раскат дня | опубликованный `index.json` |

## 1. Поле и путь

Клетки нумеруются подряд, слева направо и сверху вниз: `i = y * w + x`. Соседи — четыре
клетки по стороне, без диагоналей.

- **Расклад** — сетка `w × h`, в `k` клетках стоят номера `1..k`, между некоторыми соседями борт.
- **Путь** — список индексов клеток: каждая следующая соседняя предыдущей, борта между ними нет.
- **Раскат собран**, когда путь проходит все `w * h` клеток ровно по одному разу и номера
  встречаются в нём по возрастанию: сначала 1, потом 2, и так до `k`.
- У каждого расклада **ровно одно** решение с точностью до направления: путь и он же наоборот
  решением не считаются оба — номера задают направление, поэтому решение одно.
- **Номер 1 стоит в начале решения, номер `k` — в конце**, и у обеих клеток ровно один выход:
  остальные их рёбра закрыты бортом. Правило проверки пути этого не требует — путь законен,
  откуда бы ни начинался, — но генератор даёт только такие расклады, поэтому мини-апп может
  смело начинать ведение с номера 1, а решатель перебирает два начала вместо сорока девяти.

## 2. Опубликованные данные (сборка пишет, мини-апп и бот читают)

Каталог `webapp/data/raskat/`. `webapp/data/` в `.gitignore`, файлы собираются в задании Pages
сразу после `build_data.py`.

### `index.json`

```json
{"built": "2026-10-03T09:17:00+03:00",
 "season": "2026/27",
 "today": "2026-10-03",
 "days": [{"date": "2026-10-03", "n": 1, "w": 6, "h": 6, "k": 5, "hard": 1, "par": 70}]}
```

- `today` — день по Москве на момент сборки. Мини-апп доверяет своему устройству, но если его
  дата старше `today`, берёт `today`: часы на телефоне врут чаще, чем сборка.
- `days` — от первого дня сезона до `today` включительно, по возрастанию. Прошлые дни
  открыты как «тренировка» и в зачёт не идут.
- `n` — номер раската с начала сезона, с единицы.

### `<дата>.json` — расклад одного дня

```json
{"date": "2026-10-03", "n": 1, "w": 6, "h": 6,
 "dots": [30, 20, 8, 15, 3],
 "walls": ["3-4", "10-16"],
 "hard": 1, "par": 70,
 "lede": "Пять номеров, весь лёд за один раскат."}
```

- `dots` — индексы клеток для номеров `1..k` **по порядку**: `dots[0]` — номер 1.
- `walls` — борт между двумя соседями, `"<меньший>-<больший>"`, по возрастанию пары клеток как
  чисел (`"3-4"` раньше `"10-16"`), а не как строк.
- `par` — норма времени в секундах: по ней считаются очки (раздел 4).
- **Решения в файле нет.** Мини-апп проверяет путь сам по правилам раздела 1, сервер — так же.
  Расклад выводится из даты, так что решение всегда можно получить движком, но раздавать его
  рядом с полем незачем.

### `mock/` — для разработки без сервера

`webapp/data/raskat/mock/` с теми же `index.json` и раскладами плюс `api.js` — мок-сервера
зачётов. Включается `?raskat_mock=1`. Как в «Звене», каталог кладётся в git через `add -f`.

## 3. Движок как библиотека (сервер и сборка импортируют `raskat`)

Только stdlib. Время — `ZoneInfo("Europe/Moscow")`, наивных `datetime` в коде нет.

```python
from raskat import day_plan, generate, solve, check, points, day_points, standings
from raskat import standings as standings_module   # NB: имя standings занято функцией

day_plan(date)            # -> Plan: w, h, k, hard, par — размер и сложность по дню недели
generate(date)            # -> Puzzle: расклад дня, детерминированно по дате и соли сезона
solve(puzzle, limit=2)    # -> list[Path]: найденные решения, не больше limit
check(puzzle, path)       # -> Verdict: ok | причина отказа по-русски
points(par, seconds, streak=0, hint=False)   # -> int: итог дня, с серией (раздел 4)
day_points(par, seconds, hint=False)         # -> int: очки дня, без серии — ими ранжируют зачёт
standings(results)        # -> зачёт дня, кубок клубов и клубы без порога (раздел 4)
```

- `generate(date)` при одной дате всегда даёт один и тот же расклад: сборка на раннере и сервер
  обязаны получить одинаковое поле. Соль сезона — константа в `raskat/rules.py`, её перебивает
  переменная окружения `RASKAT_SALT`. С солью из репозитория расклад завтрашнего дня можно решить
  заранее, и «очки за время» становятся очками за «решил вечером». Закрывается одной настройкой:
  Settings → Secrets → `RASKAT_SALT` у задания Pages и то же значение на сервере. Пока секрета
  нет, живём с открытой солью: это игра болельщиков, а не киберспорт.
- `generate` отдаёт только расклады с единственным решением: проверяется `solve(puzzle, limit=2)`.
- `check` не доверяет вводу: длина, соседство, борта, порядок номеров, повторы клеток.
- Соль сервер и сборка обязаны иметь одну: иначе путь болельщика не сходится с опубликованным
  полем и зачёт отказывает всем разом. Сервер при старте сам сверяет — генерирует сегодняшний
  расклад движком и сравнивает с опубликованным файлом дня; расходится — зачёт не включается.

## 4. Очки, серия и зачёты

Счёт считают одинаково движок и мини-апп. Любая правка формулы меняет оба места и таблицу
примеров в тестах (`tests/test_raskat_points.py`).

```
база      60                       — за собранный раскат, одинаково для всех
время     до 40                    — 40 * clamp((3*par - t) / (2.5*par), 0, 1)
подсказка -20                      — одна подсказка в день, результат остаётся в зачёте
----
очки дня  = база + время + подсказка      — по ним ранжируется зачёт дня
серия     до 10                    — 2 за каждый день серии, не больше 10; в очки дня НЕ входит
итог дня  = очки дня + серия               — личное число болельщика
```

Итог округляется до целого и не бывает меньше нуля. `t` — секунды от первого касания поля до
собранного раската, без пауз. Время меньше `par / 2` очков больше не даёт: на вершине таблицы
не должно быть смысла гнать до предела. Хвост тянется до `3 * par` (`par` → 32, `2 * par` → 16),
потому что при обрыве на `2 * par` все, кто собирал раскат дольше двух норм, получали ровно 60 —
а это большая часть болельщиков в первый месяц, и кубок клубов превращался в ничью.

**Серия в зачёт дня не входит.** Иначе у новичка потолок 100 против 110 у того, кто играет
неделю, и первое место дня для него закрыто — а зачёт дня обещает «сегодня, одинаково для всех».
Серия живёт в личном числе и в своём зачёте. `streak` в `points()` — дни **до** сегодняшнего;
`Result.streak` в ответе сервера — с сегодняшним, его видит болельщик.

- **Серия** — сколько дней подряд собран раскат. Пропущенный день обнуляет серию, тренировка
  прошлого дня её не восстанавливает.
- **Зачёт дня** — список по очкам, при равенстве раньше тот, кто собрал быстрее.
- **Кубок клубов** — среднее очков дня болельщиков клуба; клуб попадает в зачёт дня, если играли
  хотя бы 5 его болельщиков. Среднее, а не сумма: иначе кубок каждый день выигрывает «Рязань-ВДВ»,
  у которой болельщиков в разы больше, а не самый упорный клуб.
- **Сезонный кубок** — среднее дневных средних по тем дням, где клуб прошёл порог, а не их сумма.
  В сезонный список клуб попадает, если прошёл порог хотя бы в половине **своих** сыгранных дней —
  тех, где играл хоть один его болельщик, а не всех дней сезона: иначе клуб, пришедший в январе,
  не попадёт в сезонный зачёт никогда, а правка была ровно против этого. При сумме
  клуб, не набравший пятерых в октябре, не догонит никогда — даже если дальше играет идеально.
- Клуб, не прошедший порог дня, из приложения не исчезает: болельщик видит честную строку
  «собрали 3, кубок считается от 5», и его собственные очки идут в зачёт дня полностью. Такие
  клубы `standings()` отдаёт отдельным списком, иначе эту строку не из чего собрать.
- Порядок в кубке при равном среднем: выше тот, у кого больше болельщиков, затем по id клуба.
  Зачёт обязан быть одинаковым при каждом пересчёте.
- Красного, «вылета» и зоны вылета в зачётах нет (DESIGN.md → «Правила»).

## 5. API сервера (`server.py`, ADR-019)

База — `https://<домен>/api/raskat`. Мини-апп берёт её из `window.RASKAT_API` (`index.html`,
подставляет задание Pages из переменной `RASKAT_API`). Пусто — играем без зачёта: поле, время,
личные записи на устройстве и кнопка «Позвать, когда откроется».

Авторизация: заголовок `Authorization: tma <Telegram.WebApp.initData>`. Сервер проверяет HMAC
(ключ — HMAC-SHA256 от токена бота со строкой `WebAppData`) и свежесть `auth_date` (24 часа).
Пользователь — только из проверенного `initData`. CORS — только адрес Pages.

Ответ об ошибке: `{"error": "текст по-русски для болельщика"}` и HTTP 4xx: 400 — путь, время или
дата не прошли проверку, 401 — вход не подтверждён или `initData` старше суток, 404 — такого дня или
дуэли нет, 409 — результат дня уже принят. Сверка соли не сошлась (раздел 3) — на всё, кроме
`DELETE /me`, 503 «Зачёт временно выключен…», причина — в `/api/health`.

| Метод и путь | Тело → ответ |
| --- | --- |
| `GET /me` | → `{"club": "ryazan-vdv" \| null, "streak": 3, "best": Result \| null, "today": Result \| null, "show_tg_name": false, "messages": true}` |
| `POST /day/<дата>` | `{path: [int], ms: int, hint: bool, club?: "ryazan-vdv"}` → `Result`. Сервер проверяет путь движком и считает очки сам |
| `GET /day/<дата>` | → `{"me": Result \| null, "top": [Row], "of": 412}` — зачёт дня, `top` не длиннее 50 |
| `GET /clubs/<дата>` | → `{"day": [ClubRow], "low": [ClubRow], "season": [ClubRow], "me": "ryazan-vdv"}` — кубок клубов |
| `GET /duel/<код>` | → `{"name": "…", "days": [{date, me, them}]}` — дуэль по ссылке `startapp=rs-<код>`. Только дни, когда играли оба, и `name` — по той же галочке `show_tg_name` |
| `POST /duel` | → `{"code": "…"}` — своя ссылка на дуэль |
| `PUT /settings` | `{show_tg_name?: bool, messages?: bool, club?: "ryazan-vdv" \| null}` → `{"club", "show_tg_name", "messages"}` |
| `DELETE /me` | → `{}` — стирает всё об игроке, зачёты пересчитываются |

```json
Result   {"date": "2026-10-03", "points": 94, "total": 102, "ms": 61200, "hint": false,
          "place": 12, "of": 412, "streak": 4}
Row      {"place": 1, "name": "Пётр К." | "Болельщик «Рязани-ВДВ»", "club": "ryazan-vdv", "points": 99, "ms": 38400, "hint": false, "me": false}
ClubRow  {"place": 1, "club": "ryazan-vdv", "avg": 86.4, "fans": 37, "days": 12, "me": true}
```

Уточнения, введённые сервером:

- **Клуб болельщика** — необязательное поле `club` (id из `teams.json`) в `POST /day` и
  `PUT /settings`: мини-апп знает любимую команду (`state.fav`) и шлёт её. Сервер запоминает
  клуб в настройках; результат дня пишется с клубом на момент раската. Поля нет — берётся
  запомненный клуб, нет и его — болельщик без клуба: в зачёт дня он идёт, в кубок клубов нет.
  Чужой id — 400.
- **`low`** в `GET /clubs` — клубы дня ниже порога: `{"place": null, "club", "avg": null, "fans": 3,
  "days": 1, "me"}`. Из них мини-апп собирает строку «собрали 3, кубок считается от 5».
- **409** отдаёт прежний `Result` вместе с полем `error`.
- **Своя ссылка** на дуэль: `GET /duel/<свой код>` → `{"name", "days": [], "own": true}`.
- **Полночь.** Принимается только раскат дня по Москве. Вчерашний — ещё 5 минут после полуночи
  (собирал до 00:00), а пока на Pages нет файла нового дня (прогон 00:05 GitHub запускает с
  опозданием) — до 02:00: мини-апп в это время честно показывает вчерашний раскат как раскат дня.
  Раньше и позже — 400 «тренировка в зачёт не идёт».
- **Имя** «Пётр К.» берётся из проверенного `initData` и хранится только пока стоит галочка
  `show_tg_name`: снял — строка имени стёрта. Без галочки `name` — «Болельщик «Рязани-ВДВ»»
  (родительный падеж — `GENITIVE` в `server.py`), без клуба — «Болельщик».

- `Result.points` — **очки дня, без серии**: по ним считается место и кубок клубов. `total` —
  итог с серией, личное число болельщика; `streak` — дни подряд, включая сегодняшний. В `Row`
  таблицы дня стоят те же очки дня.
- Результат дня принимается один раз: повторная отправка возвращает 409 и прежний `Result`.
  Тренировка прошлых дней на сервер не уходит вовсе.
- **Мини-апп шлёт раскат дня** сразу после финиша, с `club` — любимой командой. Собранный без сервера
  (`RASKAT_API` ещё пуст) или без связи уходит при следующем открытии «Раската», пока день тот же:
  запись на устройстве помечена `sent` только после ответа. 409 — прежний `Result` принимается как
  ответ; 400 — второй раз не шлём, причину показываем под табло. Пустой `RASKAT_API` из кэша Telegram
  мини-апп раз за сессию перепроверяет по свежему `index.html`, поэтому включённый зачёт открывается
  без очистки кэша.
- Имя из Telegram показывается только по галочке в настройках. Без неё в таблице — «Болельщик
  «Рязани-ВДВ»» (ADR-004: персональные данные).
- Время считает сервер по `ms` клиента, но отбрасывает невозможное: меньше **0,15 секунды на
  клетку** пути — результат в зачёт не идёт, в ответе `{"error": "…"}`. Порог именно такой:
  2 секунды на клетку — это 72 секунды на поле 6×6, то есть выше самой нормы, и такой кап
  отрезал бы не роботов, а всех быстрых болельщиков вместе с верхними очками за время.

## 6. Бот

- Диплинк `t.me/<бот>?start=raskat` и команда `/raskat` — кнопка мини-аппа `startapp=raskat`.
- Лист ожидания зачёта — в боте, без сервера: файл `raskat_waitlist.json` (не в git), отказ —
  тем же `/raskat` («Больше не звать»).
- Бот читает опубликованный `index.json`. Появился зачёт (переменная `RASKAT_API` непустая) —
  одно сообщение всем из листа ожидания, потом лист пустеет.
- Напоминание про раскат дня бот **не** шлёт, пока нет сервера: он не знает, кто уже собрал, а
  писать всем подряд каждый день — повод отключить бота.
- Мини-апп открывает «Раскат» по `startapp=raskat` и `startapp=rs-<код>`.

## 7. Общие правила (из CLAUDE.md)

- Тексты для болельщиков — по-русски: «раскат собран», «номера звена», «борт», «серия», «кубок
  клубов». Никаких «level», «score», «streak» в интерфейсе.
- Время — только `ZoneInfo("Europe/Moscow")`, наивных `datetime` нет.
- В мини-аппе всё из данных — только через `esc()`.
- Интерфейс — по `DESIGN.md`; нужно отступить — сначала `DESIGN.md`.
