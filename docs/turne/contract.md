# «Турне» — контракт реализации

Общий для четырёх частей: движок, мини-апп, сервер, бот. Правила игры — `docs/adr/017-turne.md`.
Где контракт расходится с ADR, действует ADR.

Порядок работ:

- **Ф1, без сервера:** движок, экраны, `build_turne.py`, локальные забеги. Таблиц нет.
- **Ф2, зачёт:** приём забегов, верификация, три таблицы, вымпелы.

## 1. Кто чем владеет

| Часть | Владеет | Не делает |
| --- | --- | --- |
| Движок `turne/engine/` | Правила, генерация карты, исход эпизодов, очки | Не ходит в сеть, не знает про Telegram и про хранилище |
| `build_turne.py` | Недельные данные: сид, соперники, босс, модификаторы | Не считает игру |
| Мини-апп `webapp/turne.js` | Экраны, ввод, анимация, журнал ходов | Не считает исходы — только зовёт движок |
| Сервер | Хранение забегов, верификация, таблицы | Не держит свою копию правил |
| Бот | Напоминание о туре, итог недели | Не считает игру |

Движок — единственное место, где живут правила. Сервер проверяет забеги **тем же файлом**
(`node turne/verify.mjs`), поэтому второй реализации правил в проекте быть не должно.

## 2. Опубликованные данные

### `webapp/data/turne/week.json` — неделя, собирает `build_turne.py`

```json
{
  "tour": 3,
  "from": "2026-10-19", "to": "2026-10-25",
  "seed": "turne:3",
  "boss": {"club": "polet", "mod": "press", "def": 14},
  "clubs": {
    "ryazan-vdv": {
      "opponents": ["buran", "belgorod", "tverichi", "bryansk"],
      "mood": 2,
      "home": ["buran"]
    }
  },
  "built": "2026-10-19T06:00:00+03:00"
}
```

- `opponents` — клубы, реально играющие на этой неделе, в порядке календаря; движок берёт их по
  кругу, если узлов больше.
- `mood` — «кураж»: +2 в первом матче, если клуб выиграл последний матч прошлой недели. Поражение
  модификатора не даёт (ADR-017, раздел 8).
- `def` босса считается от места в таблице на момент сборки: `10 + (27 − место) // 3`.
- Пауза в календаре: `opponents` пуст — движок берёт соперников из `history.json` и помечает узлы
  как товарищеские (вопрос 3 ADR открыт, до ответа — так).

Собирается Pages-заданием сразу после `build_data.py`, раз в сутки. Файл маленький, его читает и
мини-апп, и сервер.

### `turne/data/*.json` — контент, в git

| Файл | Что | Объём версии 1 |
| --- | --- | --- |
| `archetypes.json` | Архетипы: статы, карты, цена открытия | 8 |
| `cards.json` | Карты действий: база, стат, эффекты | 24 |
| `relics.json` | Приёмы | 12 |
| `events.json` | События узлов: текст, 2–3 выбора, эффекты | 10 |
| `bosses.json` | Особые правила боссов | 6 |

Тексты — на русском, в данных, не в коде (правило 5 CLAUDE.md).

## 3. Движок

ESM без зависимостей, Node 20+ и браузер. Чистые функции: `apply` не меняет вход, возвращает новое
состояние. Всё, что случайно, идёт только через `rng.js` от сида забега.

```js
// turne/engine/run.js
newRun(seed, week, club, options) -> State      // options: {archetypes: [...], relics: [...]}
legalActions(state) -> Action[]                  // что можно сделать прямо сейчас
apply(state, action) -> State                    // один ход; бросает на нелегальном действии
replay(seed, week, club, options, log) -> State  // прогнать журнал целиком
score(state) -> {points, nodes, goals, conceded, boss, left}
```

`Action` — плоский объект, сериализуется в журнал: `{"t": "node", "i": 1}`, `{"t": "card", "i": 2}`,
`{"t": "buy", "id": "pyatak"}`, `{"t": "event", "i": 0}`, `{"t": "start", "line": [...]}`.

`State` сериализуется в JSON целиком и несёт `v` — версию формата. Версия меняется при любой правке
правил или контента: забеги старой версии в таблицу недели не принимаются.

Детерминированность — требование контракта: `replay` от одного сида и журнала обязан дать то же
состояние на любой машине. Порядок обхода объектов нигде не влияет на результат.

### Журнал забега

```json
{
  "v": 1,
  "seed": "turne:3",
  "club": "ryazan-vdv",
  "week": "2026-10-19",
  "options": {"archetypes": ["sniper", "dispatcher", "taran", "rabotyaga", "skala"], "relics": []},
  "log": [{"t": "start", "line": [0,1,2,3,4]}, {"t": "node", "i": 0}, {"t": "card", "i": 1}],
  "claim": {"points": 180, "nodes": 5}
}
```

`claim` — то, что насчитал клиент. Сервер его **не берёт на веру**: он нужен только чтобы в логе
было видно расхождение.

### `turne/verify.mjs`

```
node turne/verify.mjs < run.json
```

Читает журнал, прогоняет `replay`, печатает JSON: `{"ok": true, "points": 180, ...}` или
`{"ok": false, "why": "нелегальный ход 14"}`. Код возврата 0 в обоих случаях, 2 — на битом вводе.
Это весь интерфейс между Python-сервером и правилами; отдельного сервиса на Node нет.

## 4. API сервера (фаза 2)

База — `https://<домен>/api/turne`, мини-апп берёт её из `window.TURNE_API` (переменная Pages
`TURNE_API`). Пусто — работает только тренировочный режим, без таблиц.

Авторизация — `initData` Telegram в заголовке, как у «Звена» (ADR-014, раздел 13).

| Метод | Путь | Что |
| --- | --- | --- |
| GET | `/week` | Текущая неделя: сид, тур, сколько зачётных попыток осталось |
| POST | `/run` | Принять забег: журнал целиком. Ответ — проверенные очки и место |
| GET | `/board/club` | Таблица болельщиков своего клуба за неделю |
| GET | `/board/league` | Общая таблица |
| GET | `/board/clubs` | Клубный зачёт: среднее по десяти лучшим забегам клуба |
| GET | `/me` | Вымпелы, открытые архетипы и приёмы |

`POST /run` считает попытку израсходованной до верификации: иначе можно перебирать исходы, отбрасывая
неудачные. Больше трёх попыток за неделю — забег принимается, но в зачёт не идёт (`"scored": false`).

Ограничения: не больше одного забега в минуту на человека, журнал не длиннее 4 КБ.

## 5. Мини-апп

- Вход — пакет «Турне» в ряду «Сегодня» на «Главной» (ADR-015), раскрывается на весь экран.
  Пятую вкладку не занимаем, она за «Звеном».
- Кольцо `--ember` на пакете — есть неиспользованная зачётная попытка.
- Экраны: карта забега, матч (рука из трёх карт, счёт, период, выносливость основы), раздевалка,
  событие, итог. Все цвета, радиусы и акценты — по `DESIGN.md`.
- Всё, что пришло из данных, — через `esc()`.
- Мок-режим `?turne_mock=1` по образцу «Звена»: `webapp/data/turne/mock/` с выдуманной неделей,
  в git через `add -f`.
- Итог забега — картинка для Stories и строка для чата (`webapp/story.html`, ADR-004).

## 6. Бот

- Понедельник, 10:00 МСК: «Новое турне. Босс недели — „Полёт“» с диплинком `t.me/<бот>?start=turne`.
- Воскресенье, 19:00 МСК: итог недели тем, кто играл, — место в клубной таблице.
- Больше бот про «Турне» ничего не шлёт: ещё один еженедельный повод писать людям мы не заводим.
- Сообщения шлёт сервер тем же токеном (как у «Звена»), бот их не дублирует.

## 8. Общие правила проекта

- Время — только `ZoneInfo("Europe/Moscow")`, наивных `datetime` нет (правило 3 CLAUDE.md).
- Тексты для болельщиков — на русском, включая ошибки (правило 5).
- Персональные данные: сервер хранит `chat_id`, клуб и забеги. Удаление — по команде боту, вместе
  с удалением из «Звена» (правило 4).
- Запросы к сайту лиги — по одному с паузой в секунду, `build_turne.py` своих запросов не делает:
  он читает то, что уже собрал `build_data.py`.
