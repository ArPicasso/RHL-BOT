## 2. Опубликованные данные (движок пишет, остальные читают)

Каталог `webapp/data/zveno/`, публикуется Pages раз в час вместе с `league.json`.
Все времена — ISO 8601 с поясом `+03:00` (МСК). Id клубов — из `teams.json`.

### `tours.json`

```json
{
  "season": "2026/27",
  "updated": "2026-10-11T10:17:00+03:00",
  "status": "prolog",              // "prolog" | "open"
  "market_opened_at": null,         // ISO, когда у всех 26 команд появился протокол 26/27
  "first_tour": null,               // номер первого тура после открытия рынка (ожидаем 1)
  "tour_now": null,                 // тур, у которого идут матчи; null в Прологе и паузе
  "tour_next": 1,                   // тур, состав на который сейчас собирают
  "tours": [
    {"t": 1, "from": "2026-10-12", "to": "2026-10-18",
     "deadline": "2026-10-12T09:00:00+03:00", "close": "2026-10-22T12:00:00+03:00",
     "closed": false,                // тур закрыт: очки окончательные
     "month": "2026-10", "circle": 1,
     "games": {"ryazan-vdv": 2, "ermak": 4, "...": 0}}
  ],
  "clubs_with_protocol": 26
}
```

21 тур, тур 12 — `2027-01-04`…`2027-01-17`, дедлайн `2027-01-09T09:00`. Тур 20 — дедлайн
`2027-03-07T23:00`. Закрытие — четверг 12:00 после последнего дня тура. `games` — число матчей клуба в
туре по календарю `league.json`.

- Дедлайн тура 12 — 09:00 дня первого матча тура по календарю (сейчас 09.01); тура 20 — всегда
  07.03 23:00; остальных — понедельник 09:00
- `close` — плановое закрытие, четверг 12:00, не меняется. `closed` — движок видит, что тур закрыт:
  прошёл `close` и протоколов не меньше двух третей матчей тура, или прошло 14 дней после `close`.
  Пока ждём протоколы — ещё `"postponed": true`
- Движок **без состояния**: каждый час считает всё по `results.json` заново. Опоздавший протокол
  попадёт и в `pool.json` у закрытого тура. Очки закрытого тура сервер берёт из своего снимка —
  делает его, когда первый раз увидел `closed: true` (ADR-014, раздел 3: после закрытия очки не меняются)
- `status` — `"open"`, когда протокол регулярки 26/27 есть у всех 26 клубов из `teams.json`
- `market_opened_at` — день матча, после которого протокол появился у последнего клуба, 23:59 МСК
- `first_tour` — первый тур с дедлайном позже `market_opened_at`: открылись в пн 12.10 днём — тур 2
- `tour_now` — тур, у которого прошёл дедлайн и не кончился последний день; только при `open` и не
  раньше `first_tour`. В Прологе, в паузе 28.12–08.01 и между воскресеньем и дедлайном — `null`
- `tour_next` — первый тур с дедлайном позже «сейчас», при `open` — не раньше `first_tour`; после
  дедлайна тура 21 — `null`

### `pool.json` — пул наклеек, стоимости и очки одним файлом

```json
{
  "updated": "2026-10-11T10:17:00+03:00",
  "tour_next": 1,
  "players": [
    {"id": "p:43454", "pid": 43454, "slot": "F", "name": "Султанов Реваль", "club": "polet",
     "number": 8, "price": 7400, "promise": 4.6, "form": true, "status": "ok", "new": false,
     "price_monday": 7200, "price_prev": 6900,
     "tours": {"1": {"m": [7, 3], "best2": 10, "ids": ["901234", "901240"]}}},
    {"id": "g:ryazan-vdv", "pid": null, "slot": "G", "name": "Ворота «Рязани-ВДВ»", "club": "ryazan-vdv",
     "number": null, "price": 8800, "promise": 6.1, "form": false, "status": "ok", "new": false,
     "price_monday": 8800, "price_prev": 8800, "tours": {}}
  ]
}
```

- `id` — ключ наклейки везде: `p:<id игрока на сайте лиги>` или `g:<id клуба>` для ворот
- `slot` — `F`, `D`, `G` (только ворота клуба)
- `status` — `ok` или `rest` («отдыхает», 4 пропущенных матча команды подряд). Скрытые
  (`hidden_players.json`) в файл не попадают вообще
- `price` — текущая стоимость по формуле ADR-014 (раздел 5 и затухание, раздел 14), шаг 100.
  `price_monday` — стоимость на последний дедлайн: от неё считается предел ±500 за тур.
  `price_prev` — на дедлайн перед ним: «Итог недели» в понедельник — `price_monday − price_prev`
- `promise` — обещание очков за матч по текущей стоимости. `form` — метка «В форме»
- `tours[t].m` — очки за каждый сыгранный матч тура в порядке дат, **без сыгранности**.
  `best2` — сумма двух лучших, тоже без сыгранности. Сыгранность и капитана считает сервер.
  `ids` — id матчей из `matches.json` в том же порядке, что `m`: к какому матчу прибавлять сыгранность.
  Матч, где игрок получил удаление до конца матча, — в `m` с нулём: он сыгран (для автозамен)
- В `tours` — только туры 1–21. Матчи Пролога (03–11.10) и паузы идут только в стоимость
- В Прологе пул пополняется по протоколам первых матчей: игрок появляется после первого протокола,
  в котором он сыграл («И» > 0). Ворота клуба — после первого протокола клуба. Полевой без id на сайте
  лиги в пул не попадает
- `slot` полевого — амплуа, в котором он чаще выходил в протоколах сезона (равенство — раньшее). Может
  смениться; наклейка в составе остаётся на своём месте, как при переходе (ADR-014, раздел 12)
- `club`, `name`, `number` — по последнему протоколу игрока (переход внутри РХЛ)
- `price_monday` — стоимость на последний прошедший дедлайн; до первого дедлайна — стартовая
  (прошлый сезон или база новичка). Предел: Пролог и туры 1–4 — ±800, дальше ±500. Стоимость
  двигается только в окне между дедлайнами, где игрок сыграл
- `promise` — обещание по формуле: `Порог + (стоимость − Мин) / Шаг`, на минимуме — `Порог − 0,4`;
  округлено до 0,1
- `form` — «В форме»: сыграл 3+ матча сезона и среднее последних 4 сыгранных не меньше обещания + 1.
  У «отдыхающего» всегда `false`. Метка только хорошая, обратной нет
- `status` у ворот всегда `ok`. «Отдыхает» — по последним 4 протоколам клуба игрока (протокол без
  составов — тоже матч клуба, который игрок пропустил)
- `new` — `true`, если нет прошлого сезона: новичок лиги, сомнительная связка по id, меньше 3 матчей
  в 25/26 или новый клуб РХЛ для ворот
- Имя ворот — «Ворота «Рязани-ВДВ»»; где родительный падеж неочевиден — «Ворота клуба «Витязь-Подольск»»
- Порядок `players` — по убыванию `price`, затем по `id`

### `matches.json` — то, что нужно серверу для сыгранности и автозамен

```json
{
  "updated": "…",
  "matches": [
    {"id": "901234", "date": "2026-10-13", "tour": 1, "home": "ryazan-vdv", "away": "belgorod",
     "settled": false,                // true после D+3 (лига больше не правит)
     "played": ["p:1", "p:2", "g:ryazan-vdv", "…"],
     "goals": [{"team": "ryazan-vdv", "author": "p:1", "assists": ["p:2", "p:3"]}]}
  ]
}
```

Голы серии буллитов в `goals` не входят.

- `id` — id матча на сайте лиги (`game_id` протокола), строкой. Только регулярка 26/27 по датам
  03.10.2026–21.03.2027 и только с протоколом; техническое поражение (счёт без составов и голов)
  пропускается
- `tour` — номер тура по датам (Пн–Вс), `null` для Пролога и паузы
- `settled` — дата матча раньше «сегодня − 3 дня», как `SETTLE_DAYS` в `league.py`
- `played` — все, кто сыграл, обеих команд и ворота обоих клубов. Скрытых игроков нет
- `goals[].author` — `null`, если у автора нет id или он скрыт; в `assists` только известные id

### `names.json` — конструктор названий

```json
{"adjectives": ["Быстрые", "Ледяные", "…"], "nouns": ["Шайбы", "Буревестники", "…"]}
```

По 40 слов, во множественном числе: любая пара согласуется. Название команды и лиги —
`[прилагательное, существительное]`, проверка — `zveno.names.is_valid(name)`.

## 3. Движок как библиотека (сервер импортирует `zveno`)

Пакет `zveno/` — только stdlib, без сети и без aiohttp. Сервер импортирует эти функции. Сигнатуры
фиксированы, внутренности — дело движка:

```python
from zveno import rules          # константы ADR-014: бюджет, слоты, лимиты, штрафы, 600 ❄, пороги
from zveno.tours import load_tours, deadline_of, close_of, tour_at, next_tour   # по tours.json
from zveno.names import is_valid                                                # название из конструктора
from zveno.manager import (
    validate_squad,     # (squad, pool, bank, *, owned=None) -> list[str] ошибок по-русски; [] — годится
    sale_price,         # (bought: int, current: int, status: str, hidden: bool=False) -> int
    tour_score,         # (lineup, captain, assistant, tour, pool, matches, *, bench=None, penalty=0) -> ScoreBreakdown
    apply_autosubs,     # (lineup, bench, tour, pool) -> (lineup, subs_made)
    fee_options,        # (tour, bank, paid_this_tour) -> list["points"|"ice"]
    mission_done,       # (lineup, album: set[str], pool) -> bool   # «Новый клуб в альбоме»
    album_clubs,        # (lineup, pool) -> set[str]   # чем пополнить альбом на дедлайн
    autopilot_pick,     # (out_id, squad, pool, bank) -> str | None   # замена «отдыхающему»
    regroup_steps,      # (managers_month_points, previous_steps, inactive_ids) -> dict[id, (step, group)]
)
```

- `lineup` — `{"G": "g:…", "L1": {"F": [id, id, id], "D": [id, id]}, "L2": {…}}`
- `bench` — `[g, d, f, f]` по порядку автозамен
- `pool` — `pool.json` целиком, его `players` или словарь `id → наклейка`; `matches` — `matches.json`
  целиком или его `matches`
- `ScoreBreakdown` — dataclass: `total`, `by_id: dict[id, {"matches": [..], "best2": n,
  "synergy": n, "mult": 1|2, "points": n}]`, `subs: list[(out, in)]`, `penalty: int`.
  `matches` и `best2` — без сыгранности, как в `pool.json`; `synergy` — прибавка к двум лучшим от
  сыгранности; `points = (best2 + synergy) · mult`; `total = Σ points − penalty`
- Время — только aware `datetime`; наивный движок не принимает (`ValueError`)

Подробности функций:

| Функция | Что важно |
| --- | --- |
| `load_tours(src=None)` | путь, уже прочитанный dict или `None` — `webapp/data/zveno/tours.json` |
| `tour_at(tours, when)` | тур по датам (Пн–Вс по Москве, тур 12 — две недели); Пролог, пауза — `None` |
| `next_tour(tours, when)` | тур, состав на который собирают: первый с дедлайном позже `when` |
| `validate_squad` | `squad = {"lineup", "bench"}`; `bank` — льдинки на наклейки, которых ещё нет в команде. `owned` — id уже взятых (или `{id: цена покупки}`): за них не платят, и лимит клуба, превышенный переходом, их не касается — «оставить можно, брать ещё нельзя». Без `owned` — сборка с нуля против `bank = 100 000` |
| `sale_price` | `bought + min(500, ⌊(current − bought)/2⌋ до 100)`; подешевела — `current`. `status == "rest"` — большее из этого и `bought`. `hidden` — большее из `bought` и `current` |
| `apply_autosubs` | слот запасного — по его месту в `bench`; встаёт на место ушедшего, в его звено; «ноль матчей» — нет матчей в `pool[id].tours[tour].m` (скрытого в пуле нет — тоже ноль) |
| `tour_score` | с `bench` сначала делает автозамены и пишет их в `subs`. Сыгранность — +1 автору и каждому ассистенту из того же звена менеджера за гол (ворота не в звене). ×2 капитану, если у него есть матчи в туре, иначе ассистенту, если у того есть матчи |
| `fee_options` | `[]` — после 2 платных за тур; `"ice"` — только в турах 1–18 и при `bank ≥ 600` |
| `mission_done` | `pool` обязателен, если в основе есть полевые: клуб берётся оттуда. Ворота — тоже клуб |
| `autopilot_pick` | `squad = {"lineup", "bench", "bought": {id: цена}}`. Кандидаты — тот же слот, `status == "ok"`, не в команде, `price ≤ bank + «Отдашь за» уходящего`, после замены не больше 3 из клуба. Выбор — самая высокая `price`, дальше `promise`, «В форме», `id`. «Мой игрок» и «Оставить» проверяет сервер |
| `regroup_steps` | ступени: 0 — Высшая (20), 1 — Первая (40), 2 — Вторая (80), 3 — Третья (160, только если менеджеров больше 400), **4 — всегда Коробка**. `previous_steps` пустой — первый сбор, все по очкам (туры 1–3). Иначе без прошлой ступени — в Коробку. Четверо лучших прошлой группы — минимум на ступень выше (из Коробки при ≤ 400 — во Вторую), пределы ступеней при этом могут превыситься, как в модели. `inactive_ids` остаются на своей ступени и занимают в ней место. Группа — номер внутри ступени с 1, по 20 по очкам, хвост меньше 10 — в предыдущую |

## 4. API сервера (сервер пишет, мини-апп читает)

База — `https://<домен>/api/zveno`. Мини-апп берёт её из `window.ZVENO_API` (index.html,
подставляет Pages-задание из переменной `ZVENO_API`). Пусто — только Пролог.

Авторизация: заголовок `Authorization: tma <Telegram.WebApp.initData>`. Сервер проверяет HMAC
(ключ — HMAC-SHA256 от токена бота со строкой `WebAppData`) и свежесть `auth_date` (24 часа).
Пользователь — только из проверенного `initData`. CORS — только адрес Pages.

Ответ об ошибке: `{"error": "текст по-русски для болельщика"}` и HTTP 4xx.

| Метод и путь | Тело → ответ |
| --- | --- |
| `GET /me` | → `{"manager": null \| Manager, "season": {status, tour_next, deadline}}` |
| `POST /team` | `{name: [прил, сущ], fav_club, lineup, bench, captain}` → `Team`. Только если команды нет |
| `GET /team?tour=N` | → `Team` на тур N (по умолчанию `tour_next`) |
| `PUT /team/lineup` | `{lineup, bench, captain}` → `Team`. Перестановка без обменов, до дедлайна |
| `POST /team/transfer` | `{out, in, pay: "free" \| "points" \| "ice"}` → `Team`. До первого дедлайна — без ограничений |
| `POST /team/boost` | `{boost: "zalivka"}` → `Team` |
| `POST /team/keep` | `{id}` → `Team` — кнопка «Оставить» для автопилота |
| `GET /leagues` | → `[{id, kind: "own"\|"club"\|"conf"\|"step"\|"month"\|"circle"\|"overall", title, place, of, points}]` |
| `GET /leagues/{id}` | → таблица: `[{place, team_name, points, me}]`. Имя из Telegram — только в своей лиге и по галочке |
| `POST /leagues` | `{name: [прил, сущ]}` → `{id, code}`. Ссылка `startapp=lg-<code>` |
| `POST /leagues/join` | `{code}` → `{id}` |
| `GET /journal` | → `[{at, kind: "deal"\|"autopilot"\|"autosub"\|"mission", text}]` — только свои |
| `PUT /settings` | `{autopilot: bool, messages: bool, show_tg_name: bool}` |
| `DELETE /me` | → `{}` — стирает всё о менеджере, таблицы пересчитываются |

### Уточнения сервера и мини-аппа (27.09.2026)

Всё — дополнения, пути и старые поля не менялись. Подробно, с кодами ошибок — `deploy/README.md`,
раздел «API».

1. `GET /me`: `manager` = `{name: [прил, сущ], title, fav_club, my_player, settings: {autopilot,
   messages, show_tg_name}, start_tour, budget, created_at}`; `season` = `{status, tour_next,
   tour_now, deadline, first_tour}`, `null` — данные ещё не загрузились. `GET /health` — без
   авторизации
2. `POST /team` — только при `status: "open"`, иначе `409`; необязательные `assistant` и
   `my_player`. «Мой игрок» автопилот не трогает, только если сервер о нём знает: мини-апп присылает
   `my_player` в `POST /team` и `PUT /settings`
3. `Team.boost` — буст на этот тур (`"zalivka"` или `null`), `boosts: {"zalivka": 1|0}` — остаток
4. `Team.unlimited: true` — обмены бесплатные и без лимита: до первого дедлайна команды
   (`tour_now: null`, `tour_next: first_tour`; у опоздавшего — до его первого дедлайна) и в тур с
   «Заливкой». Тогда `fee_options: []`, `free` не тратится
5. `points.by_id[id].total` — готовые очки наклейки с капитаном и сыгранностью (= `points`).
   Закрытый тур — снимок, `provisional: false`, `lineup`/`bench` после автозамен, `points.subs`;
   до закрытия — без автозамен. `points.penalty` — очки за платные обмены тура
6. `GET /team?tour=N`, если на тур N состава нет (пришёл после дедлайна) — `404` и `{"error"}`
7. `warnings[]`: `{id, text, in?}` — `id: null` у пустого места после скрытого игрока, `in` — кого
   поставит автопилот. Тексты предупреждений и журнала — без склонения фамилий: «Максимов пропустил
   4 матча подряд. Мишка заменит его в пн 09:00», имя проводника — `mascot.name` из `teams.json`
8. `Team.hidden` — id из состава и очков, которых нет в пуле («игрок скрыт»); `start_tour`; `value` —
   сумма «Отдашь за» без кассы; `mission` — `null` до тура 3 и в первый тур команды
9. `POST /team/transfer`: `out: null` — наклейка на пустое место своего слота. Есть бесплатный обмен —
   тратится он, какой бы ни была `pay`; «отдыхающего» отдают без расхода обмена
10. `POST /team/keep {id, keep: false}` снимает «Оставить»; `POST /team/boost` посреди окна делает
    бесплатными и уже сделанные обмены тура
11. `GET /leagues`: у `own` — `code` (ссылка `startapp=lg-<code>`) и `owner`; у `step` — `step`,
    `group`, `month`; у опоздавшего в `overall` — `since_tour`, `since_place`, `since_points`. Id:
    `own:<n>`, `club:<клуб>`, `conf:west|east`, `step:<ГГГГ-ММ>:<ступень>:<группа>`, `month:<ГГГГ-ММ>`,
    `circle:1|2`, `overall`. Очки — только закрытых туров
12. `GET /leagues/{id}` — первые 100 и своя строка; в своей лиге у строки `tg_name`, если менеджер
    поставил галочку. Чужая группа ступени — `404`
13. `PUT /settings` — частично, ещё `my_player`; отвечает `manager`. `POST /team`, `POST /leagues` — `201`

## 6. Общие правила (из CLAUDE.md)

## 7. Уточнения движка (27.09.2026)
