# Модель сезона «Звена»

Агентная модель фэнтези «Звено» (ADR-014). Нужна не для продукта, а для решений: любую новую плюшку
перед включением прогоняем здесь и сверяем с бюджетом ниже. Цифры модельные: это порядок величин, а
не прогноз.

## Что внутри

| Файл | Что делает |
| --- | --- |
| `data.py` | Собирает кэш `cache/base.pkl` из данных ниже |
| `season.py` | Сезон: очки игроков по турам, цена по формуле ADR-014 |
| `sim.py` | Менеджеры по архетипам и их решения в дедлайн. Правила и варианты — словарь `cfg` |
| `run.py` | Монте-Карло: `python3 run.py <вариант> <сезонов>` → `results/<вариант>.pkl`. Список вариантов — `VARIANTS` |
| `cmp.py` | Сравнение вариантов: `python3 cmp.py base zveno` |
| `divisions.py` | «Живая цель» и дивизионы с поправкой на уровень менеджера: `python3 divisions.py zveno` |
| `check09.py` | Вес календаря и стоимость команд к 27.12 и к концу сезона: `python3 check09.py base zveno` |
| `analyze.py`, `build_charts.py`, `owncap.py` | Сводки, данные для графиков, лимит владения |

## Данные

| Файл | Откуда |
| --- | --- |
| `../../history_protocols.json` | Протоколы НМХЛ 25/26 (ADR-008): очки по матчам, голы для сыгранности |
| `../../teams.json` | Клубы и конференции |
| `data/stat_1378.json` | Статистика всех игроков НМХЛ 25/26, `nmhl.fhr.ru/stat/players/1378/`, 26.09.2026 |
| `data/stat_1308.json` | То же за 24/25, `/stat/players/1308/`: приоры вратарских сеток |
| `data/prior_2425.json` | Очки полевых 24/25 по таблице ADR-014, связка с 25/26 по id лиги |
| `data/calendar_2627.json` | Календарь РХЛ 26/27 из опубликованного `data/league.json` мини-аппа (r-hockey, предварительный) |
| `data/tours21.json` | 21 тур «Звена», тур 12 объединён: 04–17.01 |

Когда откроется `rhl.fhr.ru` и появятся настоящие протоколы 26/27, модель стоит перекалибровать на них.

## Как проверить плюшку

Нужен `numpy`. На 4 ядрах 20 сезонов считаются около 3 минут.

```bash
cd tools/fantasy_model
python3 data.py                  # один раз: кэш данных
python3 run.py zveno 20          # принятое ядро ADR-014 — точка отсчёта
# 1. правило плюшки — флаг в cfg в sim.py; 2. вариант с этим флагом — в VARIANTS в run.py
python3 run.py <плюшка> 20
python3 cmp.py zveno <плюшка>
python3 divisions.py zveno <плюшка>
python3 check09.py zveno <плюшка>
```

Варианты `zveno` и `zveno_nodecay` — ядро ADR-014 с затуханием цены и без него. Остальные — то, что
проверяли по дороге (раздел «Экономика середины сезона» в ADR-014).

## Бюджет плюшки

Плюшка проходит, только если не ломает ни одного порога.

| Метрика | Порог |
| --- | --- |
| Вес календаря: медиана / p90 / последние 3 тура | ≤ 15% / ≤ 17% / ≤ 15% |
| Стоимость команды активного к концу сезона, медиана | ≤ +10% |
| Стоимость охотника за формой минус казуальный | ≤ 15 п. п. |
| Разрыв «активный против казуального» по очкам | ≤ +40%, не больше +3 п. п. за плюшку |
| Живая цель в туры 4–21, с поправкой на уровень (`divisions.py`) | ≥ 80% |
| Выгодных обменов (> 3 очков) у активного в туры 8–21 | ≥ 3,5 за тур |
| Подешевевших на 300+ за тур / предсказуемый остаток переоценки 300+ | ≤ 6% / ≤ 5% пула |
| Жаккар составов активных | ≤ 0,25 |
| Источников льдинок кроме старта, продажи и бюджета опоздавшего | 0 |
| Стоков льдинок кроме состава и лишнего обмена | 0 |
| Обязательных действий у казуального; сообщений бота в неделю | 0; ≤ 2 |
| Публичных негативных сигналов о конкретном игроке | 0 |

«Живая цель» в `cmp.py` и `analyze.py` считается без поправки на уровень и завышена на 10–20 п. п.
Для бюджета берём `divisions.py`.

## Допущения

- Доли архетипов и их правила экспертные: 300 менеджеров, из них 30% казуальных, 18% родителей,
  18% активных, 6% оптимизаторов, 8% охотников за формой, 10% опоздавших, 10% бросивших
- Плюс-минус и броски полевых — средние игрока за сезон: по матчам их в протоколах 25/26 нет
- Четыре новых клуба РХЛ — копии случайных клубов 25/26
- Цена льдинки для менеджера к концу сезона падает (`fee_decl`), как в прогоне Критика
